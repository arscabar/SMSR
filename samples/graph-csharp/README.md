# C# 파일 묶음 분석 예제

SMSR 저장소 색인을 갱신한 뒤 고급 분석 화면의 **C# 명시적 파일 묶음 분석**에 아래 두 경로를 입력한다.

```text
samples/graph-csharp/Library.cs
samples/graph-csharp/Entry.cs
```

기본 버전은 `CSharp12`, 조건부 심벌은 비워 둔다. `Demo.Run`은 `Converter.Format(int)`, `Demo.Echo`는 `Converter.Format(string)`에 연결되어야 한다. `Alias`는 `Converter` 타입으로 해소된다. 문자열 값과 소스 본문은 저장하지 않는다.

`Demo.Flow`의 실행 흐름 상세에서는 `if` 분기, `while` 반복의 역방향 연결, 반환을 확인한다. 변수 요약에서 `value`의 읽기/쓰기와 항상 할당 여부를 확인할 수 있다. 블록의 분기 조건은 조건 분기 열이 선택되는 기준이다. 예외 영역과 finally 경유 정보는 컴파일러 표현을 그대로 보존하며, 모든 런타임 예외 간선을 명시하는 그래프는 아니다.

입력 파일 묶음만 해석하는 예제다. 실제 프로젝트의 패키지·생성 코드·빌드 옵션을 자동으로 반영하거나 전체 프로그램 PDG/taint를 검증한 결과는 아니다. 변수 영역 요약에는 중첩 함수의 구문도 포함되므로 실행 순서나 변수 간 전파 간선으로 취급하지 않는다.

**함수 간 인자·반환 연결**에서 `Demo.Connect`의 `Choose` 호출을 펼치면 이름 있는 인자 `right`·`left`의 선언 위치 대응과 두 반환 후보가 보인다. 두 후보가 있다는 것은 두 반환이 모두 실행된다는 뜻이 아니다. 경로 조건·값 전파는 아직 계산하지 않는다. `Trim`처럼 묶음 밖의 본문은 반환 근거가 없는 상태로 표시한다.

버전 9의 `Demo.Publish`는 반환값 없는 출력 호출 예제다. `실행 흐름 상세 → 호출 인자 경로`에서 `input → System.Console.WriteLine(int)`을 펼치면 입력 읽기→`Choose` 반환 요약→변수 할당/읽기→출력 인자의 6개 간선을 확인한다. `Choose`의 기본 인자에는 함수 입력 의존이 없다. 출력 함수 본문은 외부이지만 전달되는 인자의 근원은 분석할 수 있다. 이는 실행·유출·취약점 판정이 아니라 명시적 데이터 의존 근거다.
