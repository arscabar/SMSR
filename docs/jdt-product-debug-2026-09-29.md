# Java LSP 제품 연결 검증 중 재계획

- 동일 실패3회에서 검사 반복을 중단했다. HTTP 요청 종료 중 `eclipse_11924.dll` 삭제가 거부된다. 임시 DLL 속성은 Archive이며 ReadOnly가 아니고, 실패 이후 Java 프로세스는 없다. 직접 서비스 호출은 통과하지만 같은 실행의 HTTP 호출은 실패하므로 분석 정답 실패와 구분한다.
- 앞선2회는 HTTP 상태/오류 본문 확인,3회는 직접 서비스와 HTTP 호출을 비교했다. 운영 앱/DB는 변경하지 않았다. 실패한 합성 프로젝트의 임시 폴더만 남았다.
- 새 계획: 부모 프로세스 종료만 기다리는 공통 종료 처리를 점검한다. Job Object 전체 종료를 확인한 후 임시 파일을 정리하고, 정확한 정답·HTTP/MCP·원문 보존을 다시 검증한다. 삭제 예외를 무시하거나 결과를 성공으로 바꾸지 않는다.
- 별도 검색 오류: Windows 파일명 glob을 경로 인수로 준 조회가 반복됐다. 해당 형태 재시도를 중단하고 디렉터리와 `-g` 필터만 사용한다.

## 추가 관찰과 정리 정책

Job 전체 종료 확인만 추가해도 동일 DLL 삭제 오류가 남았다. 따라서 자식 프로세스 잔여를 확정 원인으로 단정하지 않는다. Windows가 종료 직후 유지하는 파일 참조를 고려해 소유한 임시 폴더 정리에 한해250/500ms 대기 후 최대2회 재시도한다.3번째에도 실패하면 요청 실패로 전달하며 DB 결과는 정리 성공 후에만 저장한다. 읽기 전용 속성을 강제로 바꾸거나 설치/원본 폴더를 삭제하지 않는다. 잠금 파일을 사용한 정리 회귀와 실제 HTTP 검증으로 정책을 확인한다.

후속 게시본에서 직접 서비스·HTTP·실제 MCP 정의 조회와 잠금 파일 회귀가 통과했다. MCP 검사 도중에는 검사 코드의 PascalCase 인자 전달을 실제 도구 계약의 camelCase로 수정했다. 임시 정리 실패 당시 남은 합성 폴더4개는 수동 정리 명령이 도구 정책으로 거부되어 그대로 보존했다. 해당 삭제를 다른 수단으로 우회하지 않았다. 이후 성공 실행의 임시 폴더는 자체 정리됐으며 원본 프로젝트는 삭제하지 않았다.
