# 관계·설명·클라이언트 수정 검증 결과

2026-10-02. [작업계획](relationship-quality-fix-plan-2026-10-02.md)의 수정과 후보 검증을 마쳤다. 운영 앱 적용과 실제 물리 입력 검증은 완료로 취급하지 않는다.

## 수정 내용

- 공용 파일 의존 판정에서 namespace·선언 포함을 파일 간 호출로 투영하지 않는다. 실제 호출·참조와 심벌 내부 구조는 보존한다.
- 연결지도에서 병렬 관계를 분리하고, 원문 근거·추론·미해소 상태를 구분한다. 선택 심벌의 ID·경로·행을 유지한다.
- 화면 맞춤·확대·축소, 이동 후 연결선 갱신·초기화, 조회 실패 후 상태 정리를 보강했다.
- 새 지도 모듈 3개가 서버 자산 허용 목록에 빠져 실제 화면 초기화가 중단되던 HTTP 404를 수정했다. 실제 HTTP·MIME 검사도 추가했다.
- 설명은 선택 원문과 제한된 관련 구현을 사용하고 핵심 목적을 먼저 제시한다. 호출 설명은 기본적으로 해소된 원문 관계만 사용한다. 인용 링크는 실제 인용 시작 줄을 가리킨다.
- 모델 출력 스키마·프롬프트에 제공된 근거 ID와 문장당 1~4개 제한을 명시했다. 저장 검증은 완화하지 않았다. 실패에는 원문 대신 안전한 규칙 코드와 문장 위치만 남긴다.
- 생성 노트는 현재 서버 주소를 사용하며 역할·동작을 먼저, 인용 근거를 접어서 표시한다. 내부 `ROLE:` 접두사는 표시에서만 제거하며 저장 결과·추정 표시는 보존한다.
- 클라이언트의 오늘 기록 초기 조회, 프로젝트·워크플로우 선택 유지, 목록 휠 입력을 가로채던 상위 핸들러를 수정했다.

## 실제 코드 설명과 독립 원문 대조

현재 설명은 역할이 다른 네 파일을 구분한다. LLM 결과의 `CURRENT`는 지문이 맞다는 뜻이지 의미 정확도 보증이 아니다.

| --- | --- | --- |
| GraphVaultSync.cs | 연결된 보관함의 분석 노트를 동기화하고 변경 집계·충돌 목록을 반환 | 사용자 수정 보호, 제외 안내, 전체 작업 롤백 부재 |

| graph-explorer-related.js | 선택 항목의 관련 항목과 관계 원문을 화면에 제공 | 상대 노드 선택, 원문 이동, 빈 결과·오류 처리 |

최종 실제 결과는 4개 CURRENT·33문장·41개 근거다. 독립 검토에서 원문 구간·SHA256·정확한 인용 시작 행이 모두 일치했고, 관계 문장 11개가 실제 원문과 EXTRACTED/RESOLVED 관계에 부합했다. 실행 성공·임의 설계 이유를 만들지 않았다.

그러나 다음 품질 문제는 남는다.

- VaultSync의 생성 문장에는 “충돌 항목 수 반환”이 남았다. 실제 반환형은 `string[] Conflicts`이므로 **충돌 목록 반환**이 정확하다. 위 표는 이 대조 결과를 반영한 검토 요약이며, 저장된 모델 문장을 몰래 교체하지 않았다.
- 일부 복합 문장은 전체 근거에는 부합하지만 짧은 인용이 모든 서술을 직접 포함하지 않는다. 문장 분리·인용 범위 개선이 필요하다.
- `truncated`, Python의 “네임스페이스 사용권” 등은 더 쉬운 표현이 필요하다. 역할·동작의 추정 표시는 없애지 않았다.
- 이 네 파일의 통과로 전체 프로젝트·언어·사용자 만족까지 완료됐다고 판단하지 않는다.

## 관찰한 실패와 재계획

1. 최초 실제 분석은 3성공·Python 1실패(`CLAIM_EVIDENCE_IDS`). 제공 ID를 스키마에 한정했다.
2. ID 제약만 적용한 Python 재시도도 실패했다. 저장 검증에 있던 최대4개 제한이 출력 계약에 없음을 확인했다. 스키마·프롬프트를 맞추고 개수 오류를 `CLAIM_EVIDENCE_COUNT`로 구분했다.
   작업 그래프의 중간 시도 R3와 그 묶음 R은 FAILED로 보존했다. 최종 성공은 R6/D21에 따로 기록하며, 모든 하위 성공이 필요한 완료 규칙을 우회하지 않았다.
3. 최종 Python 분석은 성공했다. 다른 성공3개는 지문을 대조해 재사용했으며, 새 모델 호출을 반복하지 않았다.
4. 시험 결과 이동 중 잘못된 `revision` 필드로 요청3개가 거절됐다. 중단·기록 후 실제 계약 `expectedRevision`을 확인하고 한 요청부터 검증했다. 거절된 요청을 성공으로 집계하지 않았다.
5. 네이티브 UI 도구가 시험 창 소유자를 인식하지 못했다. 목록 갱신 뒤에도 같은 오류가 나 입력을 중단했다. 클라이언트 자체 검사를 물리 입력 합격으로 대신 표시하지 않았다.
6. 작업 폴더에서는 통과한 vis-network SRI가 게시 트리에서 실패했다. Git의 LF→CRLF 변환으로 33개 줄끝·33바이트가 바뀐 것이 원인이었다. `.gitattributes`를 해당 bundle과 Graphify vendor 경로에 한정해 원본 바이트를 보존하고 새 export를 다시 검사했다. Graphify 원본58개는 첫 export부터 지문이 같았으며 원본 코드를 수정하지 않았다.

## 남은 작업과 순서

1. 운영 앱 적용은 별도 승인 후 DB·실행본 백업 → 후보 배포 → 재시작 → 실제 오늘/프로젝트 선택/목록 휠 확인 순서로 한다. 이번 작업에서는 운영 앱을 종료하지 않았다.
2. 사용자 환경에서 Obsidian에 전용 시험 보관함을 등록하고 노트·위키 링크·원문 URI를 확인한다. 외부 Obsidian 앱 실행은 미검증이다.
3. 설명의 반환 자료형·긴 복합 주장·짧은 인용 대조를 개선하고 다양한 저장소에서 추가 의미 인수를 한다. bounded context 밖의 helper·긴 파일은 누락될 수 있다.
4. 동적 DI·외부 API·XAML 복잡 문맥·모호한 호출은 정적 분석 한계가 남는다. 정적 관계는 실제 실행 순서나 완전한 호출도를 보장하지 않는다.
5. 대형 분석 반복·동시 부하 안정성, 에이전트 ID 통합과 과거 비정상 ACTIVE 이력은 별도 범위로 확인한다.

## 증거 보관 및 게시 범위

실제4 결과: `artifacts/relationship-acceptance-20261002-final/generated-results.json`. 시험 DB·보관함과 이전 실패 결과를 로컬에 보존한다. 모델 원시 출력·사용자 원문 질문·개인 보관함은 게시하지 않는다.

게시에는 SMSR 그래프/추적/클라이언트 기능 재현에 필요한 누적 소스·검사·문서·라이선스를 포함한다. 독립 Tistory/Naver·요약 편집 기능, AGENTS 지시, DB·실행본·시험 산출물은 제외한다. 혼합 파일은 Git index에 관련 부분만 넣고 원래 작업 파일은 보존한다. 운영 배포·릴리즈는 이번 게시 범위가 아니다.

게시 안전 검사에서 자격 증명 유사 패턴1개가 발견되어 실제 원문을 확인했다. `GraphBodySelfCheck`의 알파벳 순서 합성 문자열로, 민감 본문 제외를 검증하는 fixture이며 실제 키가 아니다. 앞선 대시보드의 “패턴0” 요약은 별도 대조 노드로 정정했다. 원문 키는 문서나 로그로 출력하지 않았다.

관련 이미지29개를 실제 픽셀로 검토했고 비밀값·개인 계정 정보는 발견되지 않았다. 날짜가 있는 과거 이미지와 이전 실패 상태는 역사적 증거이며 이번 수정의 최신 화면 증명으로 사용하지 않는다. 특히 audio/media-region의 깨진 배치와 이전 drag 잘림은 당시 상태로만 보존한다. Graphify vendor의 공백은 원본 해시 보존을 위해 고치지 않았다.
