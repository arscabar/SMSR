F0 정답 자료와 실행 조건

검증 자료 규격은 정답·오연결 금지·실제 기존 검사와 아직 생성할 미디어/Office 자료를 구분합니다. 규격 정의만으로 실제 분석 시험 PASS를 주장하지 않습니다.

  • 정적 추출은 기존 SMSR Python runtime·16문법 검사와 다중 파일 oracle를 사용. F2에서 고정 원본의 지원 행렬 전체로 확장.
  • 한글 문서·없는 심벌·동명·경로 경계·취소·삭제·고아 관계·민감 이유를 필수 negative 자료로 사용.
  • 문서/미디어 모델 기본 경로는 호스트 에이전트의 구조화 결과 제출. 별도 무인 모델·provider·외부 전송·예산은 아직 결정/적용하지 않음.
  • 현재 ffmpeg와 Python/.NET 경로는 확인. 음성/vision 모델 다운로드·전사/영상 내용 분석은 미실행이며 F4 착수 때 가용성을 확인.
  • 원문 질문 로그 제외·전역 훅 미적용·명시적 저장소 참조·그래프 DB 실측 정책을 유지.
  • 측정은 실제 SMSR/AO3·5만 노드/20만 관계·대형 합성 자료. 정적 p95와 모델 대기, 냉/온 캐시·입력 수·바이트·상한을 따로 기록.

F1 구현·검증 완료

  • GraphNode의 기존 kind·ID·검색 계약을 유지하고 details에 entityKind·fileType·분석기/버전·소유 노드·선언 끝 줄·제한된 설계 이유를 보존합니다. 원본에 종류 근거가 없으면 unknown이며 모든 심벌 유형을 추정하지 않습니다.
  • 정적 관계의 원문 hash·확실성·선택적 추론 점수·생성 시각을 저장합니다. AMBIGUOUS는 기존 진단에 남기며 가짜 대상은 만들지 않습니다. 점수는 정확도 확률이 아닙니다. 생성 시각은 구조 변경 비교에서 제외하되 조회와 리비전에는 보존합니다.
  • hyperedge는 3~64개의 서로 다른 실제 노드와 역할·근거를 저장합니다. 중복·범위 밖 참여자·잘못된 hash는 전체 트랜잭션을 거부합니다. 그룹 자체를 참여자로 허용하지 않으며 pairwise 관계를 합성하지 않습니다.
  • SQLite 이행 전 .bak-knowledge 백업, 반복 이행, 사본 복원, 과거 리비전 보존을 검증했습니다. 파일 삭제·변경으로 무효가 된 그룹은 현재 조회에서 제거하고 과거 조회는 보존합니다. 구형 정보를 역산해 채우지 않습니다.
  • HTTP /api/graph/hyperedges, /api/graph/coverage와 MCP get_graph_hyperedges, get_graph_coverage를 추가했습니다. 페이지 기본 20/50, 최대 100, offset 최대 1,000,000입니다.
  • coverage는 실제 보존된 근거의 범위를 보고합니다. DETAILS_AVAILABLE / NO_SYMBOLS_OR_LEGACY / STRUCTURE_UNSUPPORTED / FILE_ONLY를 구분하며 빈 파일의 분석 실패나 전체 관계의 완전성을 추정하지 않습니다.
  • 색인 형식을 v12로 변경했습니다. 기존 프로젝트는 다음 사용자 색인 때 메타데이터를 다시 추출하며 지금 자동 전체 색인하거나 원본 vendor를 갱신하지 않았습니다.

운영 앱 적용과 대형 조회 보강

사용자 승인 후 검증 출력을 현재 실행 경로 src/SMSR.App/bin/Release/net8.0-windows에 반영하고 기존 주소 http://127.0.0.1:49783로 재시작했습니다. 실행 파일 백업은 artifacts/app-deploy-backup-20261001-1147와 보강 전 artifacts/app-deploy-backup-20261001-1151입니다. 운영 DB 이행 전 백업 smsr.db.bak-knowledge-20261001-024707590가 생성됐습니다. 재시작 때 --skip-codex-integration을 사용해 자동 재설정을 생략했고 전후 Codex config.toml·hooks.json의 지문이 동일합니다.

첫 운영 AO3 조회는 리비전 전체에 파일별 심벌 조인을 반복해 MCP 제한 시간을 넘겼습니다. 계획 조회에서 소유 경로 인덱스 부재를 확인하고 복합 인덱스 및 파일 페이지 선조회를 적용했습니다. 재검증 HTTP 1/100/1개 페이지는 각각 3988/493/412ms였고 MCP도 정상 응답했습니다. 이는 3회 실측이며 p95 벤치마크나 전 규모 성능 보장은 아닙니다. 기존 AO3 리비전 9의 2603파일·17778심벌은 구형 세부 정보로 표시되며, 다음 사용자 색인 때 v12 정보를 추출합니다. hyperedge가 없는 기존 자료에 그룹을 임의 합성하지 않았습니다.

운영 화면에서도 이력·순서를 접고 상세를 펼친 상태가 heartbeat에 따른 실제 DOM 갱신 후 유지됐습니다. 운영 화면 증빙.

F2~F8은 미착수입니다. Office·미디어 자료 규격이 있어도 실제 의미 추출·전사·영상 모델 검증을 했다는 뜻은 아닙니다. 그래프 활용 스킬·본문 의미 관계·언어 확장·커뮤니티 고도화·피드백 재사용·감시·지식 내보내기는 후속 단계입니다. 운영 앱 적용은 완료했지만 Git 커밋/푸시/릴리즈는 수행하지 않았습니다.
