## 2. 성능과 운영 자료

최신 `artifacts/live-p1-final/SMSR.App.exe` 기준:

| 항목 | 실측 |
|---|---|
| 합성 조회 규모 | 파일 5,000 / 노드 50,000 / 관계 200,000 |
| 측정 횟수·목표 | 40회 / p95 ≤2,000ms |
| 경로·역방향 영향 p95 | 74.7747ms / 83.5877ms |
| 시험 DB 크기 | 71,397,376바이트; 현재 그래프+리비전 스냅샷 포함 |
| 색인 중 응답 시험 | 1,000파일 / 21,000노드 / 40,000관계, 색인 2,510.6ms |
| 동시 응답 확인 | 77회, 최대 120.9ms; HTTP 응답성의 대리지표이며 WPF 프레임률 측정은 아님 |
| 실제 저장소 중간 검증 | 리비전 5, 345파일 / 898노드 / 595관계; 고아·자가·중복 0 |
| 실제 미해소 2건 | 가이드·계획서의 의도적인 인용 문법 예시. 실재 파일로 오연결하지 않음 |

실측이 초기 목표를 충족하므로 SQLite 원본을 유지한다. 장기 리비전 누적과 다중 실제 대형 저장소 성능은 별도 관찰 대상이다. 위 실제 색인 수치는 문서 추가 전 값이며 최종 보고서/계획서 갱신 후 재색인하면 증가한다.

운영 DB의 온라인 스냅샷을 **별도 새 파일**에 복원했다. 전체 테이블 행 수 일치, `integrity_check=ok`, 외래키 위반 0을 확인했다. 운영 DB는 덮어쓰지 않았다. 초기 검증 사본은 `%LOCALAPPDATA%/SMSR/verification-backups/20260928-120047-377209/`, 최종 실행본 사본은 `20260928-121101-226238/`에 보존했다.

## 3. 재현 명령

```powershell
dotnet build src/SMSR.App/SMSR.App.csproj -c Release --no-restore
dotnet publish src/SMSR.App/SMSR.App.csproj -c Release --no-restore -o artifacts/live-p1-final
$app = (Resolve-Path artifacts/live-p1-final/SMSR.App.exe).Path
foreach ($check in @('--graph-self-test','--graph-advanced-self-test','--tracking-self-test','--codex-config-self-test','--self-test','--graph-benchmark','--graph-responsiveness-self-test')) {
    $result = Start-Process $app -ArgumentList $check -WindowStyle Hidden -Wait -PassThru
    if ($result.ExitCode -ne 0) { throw "$check failed: $($result.ExitCode)" }
}
./scripts/test-mcp-stdio.ps1 -ApplicationPath $app
python scripts/verify-graph-backup.py
git diff --check
```

모든 자체검사는 종료 코드 0, Release 빌드는 경고/오류 0이었다. GUI 실행 파일이므로 단순 호출 완료가 아닌 프로세스 종료 코드를 확인한다. 성능 JSON은 `%TEMP%/smsr-graph-benchmark.json`, `%TEMP%/smsr-p1-responsiveness.json`에 생성된다.

## 4. 남는 경계와 출시 확인

- 전체 스크린리더 사용성, 실제 한국어 IME 조합 입력, 별도 PC 설치/업데이트/코드서명은 이번 자동화에서 검수하지 않았다. 한글 검색·접근성 이름·키보드 Enter 검증과 구분한다.
- 기존 AO3.5 과거 작업의 누락된 실행 결과를 추정 복원하거나 하위 노드를 강제로 성공 처리하지 않았다. 구기록은 실제 실행 근거에 따라 별도 정리해야 한다.
- 원문 질문 로그는 제외했고 전역 Git 훅은 설치 기능만 제공한다. 실제 `core.hooksPath`는 변경하지 않았다.
- P2의 전 언어 의미 정확도, 타입/별칭 해소, 함수간 정밀 PDG, 본문 의미 검색은 미구현이다. 구문/메타데이터 분석으로 대체 완료했다고 표시하지 않는다.
- 경로·문서 제목 자체에 비밀을 넣으면 메타데이터에도 노출될 수 있다. 기본 필터는 모든 비밀을 판별하는 DLP가 아니므로 저장소의 민감 경로 정책을 유지해야 한다.
- 리비전 전체 스냅샷은 DB를 늘린다. 삭제/보관 정책 도입 전 운영 크기를 측정하고 사용자 동의 없이 과거 기록을 삭제하지 않는다.

최종 출시 승인은 사용자에게 남긴다. 이 보고서의 완료 판정은 P1 기능 개발·회귀·실행본 smoke·복원 검증에 한정한다.
