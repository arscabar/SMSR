# 설명 일괄 생성·Obsidian 연동 작업계획

## 목표·범위

- 승인된 계획: 코드 파일의 전체/폴더별 설명 생성, 진행 제어, 변경 근거 갱신 및 보호된 Obsidian 노트 동기화.
- 기존 SQLite 역할 설명·대기열·관계 근거를 재사용한다. 문서/매체의 기존 색인·분석 경로는 유지한다.
- 제외: 클라우드 동기화, 신규 Obsidian 플러그인, 전용 그래프 DB, Git 게시, 기존 사용자 보관함의 임의 변경.

## 검증·산출물

Release 빌드, C# 계약/HTTP 검사, JS 상호작용 검사, 임시 보관함 보호 검사, 실제 브라우저 확인. 코드·테스트·사용법과 실행 결과를 남긴다. 인용 일치는 의미 정확성 증명이 아니며 설명 범위 제한과 미해소 관계를 유지한다. 같은 원인의 실패 3회 시 재시도를 중단한다.

## 사용자 결정

앱에서 기존 보관함 또는 새 전용 보관함 경로를 선택한다. 승인되지 않은 기존 보관함에는 쓰지 않는다. 일괄 설명 시작 시 대상과 Codex 사용량 소비를 확인한다.

## 인수 결과

A1~A3·B1~B5·C1~C3·G1 및 승인된 D1~D2 구현·검증·현재 앱 적용을 완료했다. Release 경고0·오류0, 역할/보관함/HTTP·지식·전체 그래프 회귀 exit0, JS 상호작용 PASS. 일반 샘플의 노트8개 최초 생성·반복 갱신0, 최신 설명 재사용 완료1/1, 운영 그래프 전체 행 보존을 확인했다. 상세 실행·백업·제약은 [개발 이력](development-log/2026-10-02.md)에 기록했다.

아직 사용하지 않은 운영 기능과 미검증 외부 환경을 구분한다. 전체 운영 파일의 LLM 설명을 자동 실행하지 않았으며 개인 보관함은 연결하지 않았다. 실제 Obsidian 앱 열기는 사용자 설치·등록 후 확인해야 한다. 과거 Git 오류는 이번 회귀에서 재현되지 않았고 근본 원인 수정으로 단정하지 않는다.
