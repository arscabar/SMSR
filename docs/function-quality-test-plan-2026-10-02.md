# 전체 기능·결과 품질 인수 계획

## 목표·범위

승인한 범위는 기존 자동 기능 검사, 실제 웹 상호작용, 대표 실제 코드 3~5개에 대한 읽기 전용 Codex 설명 생성, 전용 테스트 보관함의 노트·근거 품질 확인이다. 기존 개인 보관함·전역 훅 설정·전체 프로젝트 LLM 분석·Git 게시·기능 수정은 제외한다. 실패와 미검증을 통과로 합산하지 않는다.

## 작업·완료 기준

| ID | 상위 | 선행 | 담당 | 완료 기준 |
|---|---|---|---|---|
| A1 | 자동 검사 | 없음 | 주 에이전트 | 검사 목록·격리·현재 실행본 기준 확인 |
| A2 | 자동 검사 | A1 | JS 검사 에이전트 | 기존 JS 기능 검사 실행·개별 결과 |
| A3 | 자동 검사 | A1 | .NET 검사 에이전트 | 안전한 자체 검사 실행·오류·제외 범위 |
| B1 | 실제 설명 | A1 | 주 에이전트 | 대표 실제 코드 3~5개 생성·저장·결과 보존 |
| B2 | 실제 설명 | B1 | 품질 검토 에이전트 | 원문과 문장·관계 대조·과장·누락·이해 가능성 판정 |
| C1 | 화면·노트 | B1 | 주 에이전트 | 검색·선택·범위·진행·연결·동기화 실제 화면 확인 |
| C2 | 화면·노트 | C1 | 주 에이전트 | 사용자 수정·동일 내용 미쓰기·오래됨·DB 보호 확인 |
| D1 | 보고 | A2,A3,B2,C2 | 주 에이전트 | 통과/실패/미검증·출력 예시·품질 판단·다음 조치 |

A2·A3·B1은 독립 실행 가능하다. B2와 C1도 독립 실행 가능하다. 같은 원인의 실패 3회 시 재시도를 중단한다.

## 검증·산출물·결정

기존 CLI/JS 자체 검사, 임시 DB·보관함, 실제 브라우저 및 원문 대조를 사용한다. 검사 보고서와 날짜별 이력을 남긴다. LLM 인용 검증 통과와 의미 정확성은 별도 평가한다. 실제 Obsidian 앱이 없거나 UI 조작이 불가능하면 외부 앱 인수는 미검증으로 기록한다. 사용자 승인: 위 범위로 진행.
