# 대형 합성 그래프 HTTP 성능·정답 검사 — 2026-09-29

결론: **이번 5만 노드·20만 관계 합성 부하에서 SQLite는 p95 2초 기준을 통과했다.** 전용 DB로 교체할 성능상 필요는 이 시험에서 확인되지 않았다. 다른 DB보다 빠르다는 비교 결과나 P2 전체 성능 완료를 의미하지 않는다.

## 이전 검사에서 보완한 점

기존 `--graph-benchmark`는 서비스 직접 호출로 한 단계 경로의 발견 여부만 검사했고 영향도 응답은 정답과 대조하지 않았다. p95 초과도 보고서의 false만 기록하고 정상 종료했다. 기존 수치는 당시 제한된 방법의 이력으로 남긴다.

버전2 검사는 실제 loopback HTTP·JSON 해석까지 측정한다. 별도 산술 BFS로 최단 거리, 반환 간선의 연속성/끝점/관계/소유권, 역방향 영향 집합의 누락/중복과 노드 속성을 확인한다. 리비전·그래프 개수·무결성·깊이 제한 표시도 검사한다. 잘못된 결과나 p95 초과는 비정상 종료한다.

## 데이터·환경

- SQL fixture: 파일 기록5,000, 노드50,000, 유향 간선200,000. 실제 파일5,000개를 색인한 시험은 아니다.
- 노드0~49,999에서 각각 +1/+2/+101/+1001 modulo50,000으로 연결하는 균일 차수 순환 그래프. 실제 저장소의 고차수 허브·여러 커뮤니티·단절 분포를 대표하지 않는다.
- 각 반복은 새 임시 DB·새 앱 프로세스·임의 loopback 포트의 서버를 생성한다. 종료 시 검증 전용 임시 폴더를 정리한다. 운영 DB와 실행 앱은 교체하지 않았다.
- DB 본체71,397,376바이트. 현재/리비전 관계와 SMSR 기본 스키마를 포함한다. 운영 DB 증가량·색인 원문·JDK/모델 크기가 아니며 WAL/SHM·프로세스 메모리를 합산하지 않는다.
- Windows11 Pro10.0.26200, i5-12400F, 논리12CPU, RAM17,026,113,536바이트. OS 캐시를 지우거나 CPU를 고정하지 않았다. 첫 게시 측정에는 별도 그래프 자체검사가 함께 실행됐으며 나머지 두 번에는 이 작업의 다른 검사를 겹치지 않았다. 다른 사용자 앱 부하는 통제하지 않았다.
- 게시본: `artifacts/verify-p2-large-graph`. 실행 코드를 식별하는 `SMSR.App.dll` SHA-256: `70DB8DE084F93EBC9CF4831D39790DF3BBE3037B52CBFFE6E5D55D2F6B934BB9`. 네이티브 .exe apphost 해시만으로는 관리 코드 변경을 구분할 수 없다.

## 표본·판정

1. 시작 노드는 `i*997 % 50000`. 경로 목표의 상대 거리는 `[0,1,1001,1102,2103,3104,4105,49000]`를 순환한다. 경로 최대 깊이5·노드1,000, 영향도 깊이1~5·노드100으로 공개 HTTP 경로를 사용한다.
2. 유형별 예열5회 후40회 측정한다. 경로의 최단 길이0/2/3/4/5와 깊이 내 미도달은 각5개, 길이1은10개다. 미도달5개는 전역 단절이 아니라 **5단계 안에서 못 찾은 깊이 제한**이며 `Truncated=true`가 필요하다.
3. 영향도는 깊이별4/13/29/54/90개 전체 집합과 비교한다. 노드100개 상한에 걸리지는 않는다. 더 깊은 관계가 존재하므로 응답의 `Truncated=true`는 예상된 깊이 제한이다. 결과 순서는 정답으로 강제하지 않는다.
4. 요청 시작부터 HTTP 응답 JSON 해석까지 잰다. 독립 정답 검사는 시간에서 제외한다. p95는 정렬40표본의38번째 값이다. NaN/무한대/음수·표본 수 오류를 거부한다. 경로·영향도 중 하나라도2,000ms를 넘으면 실패한다.
5. 검증기의 음성 검사에는 잘못된 끝점/비최단 경로·리비전/잘림 오류·누락/중복 영향·잘못된 노드 속성·목표 초과가 포함된다. 그래프 회귀와 기존 소형 실제 저장소 정답 도구도 통과했다.

## 재현

```powershell
dotnet publish src/SMSR.App/SMSR.App.csproj -c Release --no-restore -o artifacts/verify-p2-large-graph
$app=(Resolve-Path artifacts/verify-p2-large-graph/SMSR.App.exe).Path
$result=Start-Process -FilePath $app -ArgumentList '--graph-benchmark' -WindowStyle Hidden -Wait -PassThru
if($result.ExitCode -ne 0){throw 'Benchmark failed; inspect smsr-graph-benchmark-error.txt in TEMP'}
Get-Content "$env:TEMP/smsr-graph-benchmark.json"
```

먼저 프로세스 종료 코드를 확인한다. 정답 검사 도중 실패하면 이전 실행의 JSON 파일이 남을 수 있으므로 파일 존재만으로 통과를 판단하지 않는다. 보고서 `version=2`·시각·목표 판정을 함께 확인한다. 새 빌드의 DLL 해시는 달라질 수 있다.
