# SMSR 작업 관제 기능 확장 개발계획서

> 작성 기준: 2026-09-16
>
> 이 계획서는 현재 SMSR 구조를 유지하면서 작업 상태의 신뢰성, 계획 분해, 사용자 개입, 요약·질의, 사용자 등록 펫을 단계적으로 확장하기 위한 실행 계획이다. 날짜 기반 일정은 정하지 않고 기능 단계와 완료 게이트로 관리한다.

## 1. 프로젝트 범위와 목표

### 1.1 배경

SMSR은 Codex와 로컬 MCP가 기록한 계획·이벤트·heartbeat를 SQLite에 저장하고, WPF 앱과 브라우저 대시보드에서 작업 그래프를 보여준다. 현재 가장 중요한 문제는 작업이 큰 노드 하나로 뭉쳐지거나, 진행 중인지 정체되었는지, 사용자가 무엇을 결정해야 하는지가 즉시 보이지 않는다는 점이다.

### 1.2 핵심 목표

1. 사용자가 5초 안에 현재 작업, 마지막 활동, 정체 여부, 차단 이유를 파악한다.
2. 독립적으로 추적할 수 있는 작업은 A1·A2 하위 노드로 분리되고 부모 진행률에 정확히 반영된다.
3. 선택한 노드의 기록만 작업 상세에 표시하고, 결과·오류·완료 기준·사용자 결정이 섞이지 않게 한다.
4. 요약과 질의는 선택한 프로젝트·그래프·기간·노드의 저장 데이터만 근거로 사용한다.
5. 사용자가 등록한 펫 1마리가 선택된 활성 그래프의 상태를 읽기 전용으로 표현한다.

### 1.3 성공 지표

| 영역 | 성공 기준 |
|---|---|
| 상태 신뢰성 | 동일 이벤트 재수신 시 중복이 없고, 마지막 이벤트·heartbeat·오류 시각이 일관되게 표시됨 |
| 정체 판정 | 설정된 임계시간 동안 의미 있는 변화가 없으면 `정체 가능성`으로 표시되고, 실패·차단·중단과 구분됨 |
| 계획 품질 | 독립 결과가 두 개 이상인 포괄 리프에 분해 경고가 표시되고, 승인된 `children`이 `parentNodeId` 계층으로 저장됨 |
| 상세 화면 | 선택 노드의 상태 기록·활동·산출물만 표시되며 다른 노드의 기록이 섞이지 않음 |
| 질의 | 답변 범위, 기준 시각, 근거 노드·이벤트와 모델 오류가 표시됨 |
| 펫 | 등록된 한 마리가 선택 그래프·현재 노드 상태와 동기화되고, 펫이 독립적인 작업 상태를 만들지 않음 |
| 배포 | Release 빌드·자체검사·stdio·설치본 검증이 통과하고 기존 SMSR 프로세스를 불필요하게 종료하지 않음 |

### 1.4 주요 사용자

- 로컬 Windows 환경에서 Codex 작업을 단독으로 관제하는 사용자
- 여러 프로젝트와 워크플로우의 진행·차단·실패 원인을 확인해야 하는 개발자
- 작업을 다른 사람에게 넘기거나 완료 결과를 회고해야 하는 사용자

### 1.5 범위

#### 포함

- 계획·노드 상태 계약 보강
- heartbeat·이벤트 기반 정체·중단 판정
- 활성 그래프 요약과 차단 작업함
- 노드별 상세·타임라인·기록 필터
- `children` 기반 계획 분해 품질 검사
- 선택 범위 기반 AI 요약·질의와 모델 오류·대체 모델 안내
- 사용자 등록 펫 1마리, 그래프 선택, 상태별 표현, 트레이 제어
- 검색·필터·인수인계 내보내기·작업 템플릿의 단계적 도입
- 자체검사·설치본·프로세스 보존 검증

#### 제외

- 벡터 DB, 자동 지식 그래프, 전체 원문 자동 임베딩
- 다중 펫과 게임화·점수·레벨 시스템
- 원격 접속, 클라우드 동기화, 다중 사용자 권한
- 사용자 승인 없는 재시작·취소·에이전트 강제 제어
- 시간만으로 하위 작업을 추측하는 자동 그래프 생성
- 외부 서비스 다중 연동과 무제한 원시 로그 스트리밍

### 1.6 우선순위

| 우선순위 | 범위 |
|---|---|
| P0 | 상태 의미 통일, 정체·중단 감지, 차단 작업함, 활성 그래프 요약, 노드별 상세 |
| P1 | 계획 분해 검사, 근거 기반 요약·질의, 펫 등록·그래프 연결, 검색·필터, 백업 |
| P2 | 타임라인 재생, 인수인계 패키지, 작업 템플릿, 실행 통계·비교 |
| 보류 | 벡터화·지식 그래프, 다중 펫, 클라우드·외부 연동 |

### 1.7 v1.5.0 구현 현황과 다음 우선순위

| 구분 | 상태 | 내용 |
|---|---|---|
| 상태·관제 | 1차 완료 | 완료 그래프 문구, 정체 가능·차단·실패 수, 선택 노드 상세·활동 필터 |
| 계획 품질 | 완료 | `children` 평탄화, `parentNodeId` 드릴다운, 의존성·순환 검증 |
| 요약·질의 | 1차 완료 | 특정/전체 프로젝트, 오늘/선택 기간, Gemini 오류·대체 모델 안내, IME 갱신 분리 |
| 단일 펫 | 1차 완료 | 안전한 이미지 복사, 선택 그래프 상태·진행률, 트레이 표시·숨김 |
| 토큰 관제 | 1차 완료 | 현재 목표 작업과 그래프 연결 이후의 IN/OUT 구분, 미제공 시 `수집 대기` |
| 운영 고도화 | 다음 | 실제 화면 수용 검사, 검색·필터, 인수인계 묶음, 펫 접근성 설정 |
| 보류 | 유지 | 벡터 DB·지식 그래프, 다중 펫, 클라우드 동기화 |

토큰 관제는 Codex 로컬 세션에 보고된 수치만 사용하며 원문을 저장하지 않는다. 공개 사용량 계약이 제공되면 입력부만 교체하고, 기존 기록은 추정치로 소급하지 않는다.

## 2. 현재 구조와 기술 방향

기존 구조를 유지한다. 새 서버나 저장소를 추가하지 않고 현재 계약과 패턴을 확장한다.

```text
WPF App / Tray
  ├─ 설정·프로젝트·그래프 선택
  ├─ 단일 펫 등록·표시 설정
  └─ 로컬 서버 상태·알림·대시보드 열기

ASP.NET Core Kestrel (127.0.0.1)
  ├─ MCP 계획·이벤트·heartbeat 도구
  ├─ 상태 projection 및 정체 판정
  ├─ Dashboard HTML/SSE
  └─ 요약·질의 범위와 결과 관리

SQLite + Activity JSONL
  ├─ 계획·노드·상태·이벤트
  ├─ 에이전트 활동·heartbeat
  └─ 요약 요청·결과·사용자 결정

Browser Dashboard
  ├─ 활성 그래프 요약
  ├─ 계층형 그래프·노드 상세
  ├─ 차단·정체 작업
  └─ 기간·프로젝트·상태 필터
```

AI는 사실의 원천이 아니다. 상태·시간·노드 관계는 SQLite와 이벤트 projection에서 결정하고, Gemini 또는 대체 모델은 저장된 범위를 설명하는 데만 사용한다.

## 3. 기능 설계

### 3.1 상태·정체·중단

- 상태를 `PENDING`, `IN_PROGRESS`, `VALIDATING`, `RETRYING`, `SUCCESS`, `FAILED`, `BLOCKED`, `CANCELLED`로 구분한다.
- `lastEventAt`, `lastHeartbeatAt`, `updatedAt`, `error`, `nextAction`을 분리한다.
- heartbeat만 있고 의미 있는 이벤트가 없으면 작업 중이 아니라 `정체 가능성`으로 표시할 수 있다.
- 부모는 자식이 남아 있으면 성공으로 확정하지 않는다.
- `CANCELLED`는 미완료 상태로 넘어간 경우, `FAILED`는 오류가 확인된 경우에만 사용한다.
- 상태 판정은 서버에서 수행하고, 화면은 projection 결과를 표시한다.

### 3.2 활성 그래프와 차단 작업함

- 현재 선택된 프로젝트·워크플로우의 요약을 상단에 표시한다.
- 현재 노드, 전체 진행률, 마지막 활동, 정체 가능성, 차단 수, 실패 수를 보여준다.
- 차단 작업함은 사용자 결정, 인증 만료, 외부 조건 대기, 검증 실패를 분류한다.
- 각 카드에는 `문제`, `근거`, `선택 가능한 조치`, `결정 후 재개할 노드`를 표시한다.
- 자동 재시작은 하지 않고, 사용자의 확인과 기록을 거친다.

### 3.3 계획 분해 품질

- `save_plan`의 `children`을 서버에서 안전하게 평탄화해 `parentNodeId`로 저장한다.
- 독립적으로 진행·중단·실패·완료를 판단할 결과가 두 개 이상인 포괄 리프에는 경고를 표시한다.
- 분해 후보를 AI가 제안할 수는 있지만, 실제 저장은 사용자 또는 계획 에이전트의 명시적 입력을 사용한다.
- 성공 노드에 새 자식을 붙이지 않는다.
- 의존성·중복 ID·순환·완료 기준 누락을 저장 전에 검증한다.

### 3.4 노드별 상세와 타임라인

선택한 노드 기준으로만 다음 정보를 보여준다.

- 제목과 상태
- 담당자·역할
- 현재 작업 또는 결과
- 오류·재시도 횟수
- 완료 기준
- 산출물
- 해당 노드의 활동·상태 변경 기록
- 사용자가 결정해야 하는 내용

전체 그래프의 다음 노드를 반복해서 글로 적지 않는다. 다음 단계는 실제 사용자 조치가 필요한 경우에만 표시한다.

### 3.5 요약·질의

- 요약 팝업에서 자료 생성과 질의를 분리한다.
- 팝업의 프로젝트 범위는 현재 그래프 선택과 분리하며, 특정 프로젝트 또는 전체 프로젝트를 선택한다.
- 오늘 버튼은 선택한 프로젝트 범위의 오늘 기록을, 선택 기간 버튼은 달력의 단일 날짜 또는 기간 기록을 사용한다.
- 질의 범위를 프로젝트·워크플로우·기간·선택 노드로 고정한다.
- 답변에는 기준 시각, 근거 이벤트·노드, 사용 모델, 실패 또는 대체 모델 사용 여부를 표시한다.
- Gemini 호출 실패 시 “미연결”로 뭉뚱그리지 않고 인증·모델·할당량·서버 오류를 구분한다.
- 한글 입력 조합을 방해하지 않도록 입력창은 상태 갱신과 분리하고, IME 조합 중에는 재렌더링하지 않는다.

### 3.6 사용자 등록 펫 1마리

- 사용자가 펫 이름과 허용된 이미지·애니메이션 자산을 등록한다.
- 등록 자산은 지정 디렉터리 밖을 참조하지 않고, 실행 가능한 파일이나 스크립트는 허용하지 않는다.
- 트레이에서 펫 표시·숨김, 크기, 투명도, 항상 위, 움직임 감소를 설정한다.
- 펫은 현재 선택된 활성 그래프 하나를 따른다.
- 상태 표현 예시:
  - `PENDING`: 대기·호흡
  - `IN_PROGRESS`: 작업 중
  - `VALIDATING`: 확인·관찰
  - `RETRYING`: 정비·재시도
  - `BLOCKED`: 도움 요청
  - `FAILED`: 경고
  - `SUCCESS`: 짧은 완료 동작 후 휴식
  - `CANCELLED`: 중단·휴식
- 그래프가 종료되면 펫은 자동으로 다른 그래프로 이동하지 않고 대기한다. 사용자가 선택하면 전환한다.
- 펫은 사실을 기록하거나 상태를 판단하지 않고, 서버 projection을 읽기만 한다.

### 3.7 후속 고도화

- 기록 검색·필터·기간별 비교
- 그래프 실행 타임라인 재생
- 인수인계용 HTML·Markdown·JSON 묶음
- 배포·버그 수정·검증 작업 템플릿
- 평균 소요 시간·재시도·반복 실패 통계
- 벡터 DB는 구조화된 기록만으로 검색이 부족하다는 근거가 생긴 뒤 별도 검토

## 4. 팀 구성과 역할

실제 인력은 1인 개발을 기본으로 하며, 아래 역할을 작업 단위로 분리한다. Codex 에이전트는 각 역할의 초안·검사·문서화를 보조한다.

| 역할 | 책임 | 주요 산출물 |
|---|---|---|
| PM/제품 담당 | 범위·우선순위·완료 기준 결정 | 요구사항, 결정 로그 |
| 아키텍트 | 현재 WPF·Kestrel·SQLite 구조 안의 계약 설계 | 상태·이벤트·펫 연동 설계 |
| 상태/백엔드 담당 | projection, 정체 판정, 계획 검증, MCP 계약 | 서버 코드, 데이터 계약, 자체검사 |
| 대시보드 UX 담당 | 활성 그래프·차단함·노드 상세·타임라인 | HTML/CSS, 화면 계약 |
| AI 기능 담당 | 요약·질의 범위, 오류 분류, IME 입력 안정화 | 프롬프트·응답 계약·fallback |
| 펫 UX 담당 | 등록·자산 검증·상태 애니메이션·트레이 연결 | 펫 자산 계약, WPF 오버레이 |
| QA/릴리스 담당 | 회귀·설치·프로세스 보존·릴리스 검증 | 테스트 보고서, 설치본, 체크섬 |

## 5. 단계와 완료 게이트

날짜나 주차는 정하지 않고 아래 순서로 진행한다. 다음 단계는 이전 게이트가 통과된 뒤 시작한다.

### Gate A — 상태 기반 확정

- 상태 의미와 projection 필드 확정
- 중복 이벤트·heartbeat·부모 진행률 계약 테스트
- 정체·실패·차단·중단 화면 문구 확정

### Gate B — 관제 화면

- 활성 그래프 요약
- 차단 작업함
- 노드별 상세·활동 필터
- SSE 갱신 후 선택·스크롤 상태 보존

### Gate C — 계획 품질

- `children` 평탄화와 `parentNodeId` 저장
- 포괄 리프 분해 경고
- 의존성·완료 기준·순환 검증
- A1/A2 예제 자체검사

### Gate D — 요약·질의

- 선택 범위 기반 자료 생성
- 질의 팝업과 근거 표시
- 모델 실패 분류와 대체 모델 안내
- 한글 IME 입력 회귀 검사

### Gate E — 단일 펫

- 펫 등록·교체·삭제
- 선택 그래프 연결
- 상태별 표현과 완료 후 대기
- 트레이 메뉴·접근성·자산 보안 검사

### Gate F — 운영 고도화와 릴리스

- 검색·필터·내보내기·템플릿 중 우선 항목 선정
- 전체 자체검사·stdio·설치본·프로세스 보존 확인
- 설치본과 개발 문서 동기화

## 8. QA와 테스트 계획

### 테스트 전략

기존 자체검사 체계를 유지하고 계약·통합·화면·설치 검사를 단계별로 추가한다. 테스트는 실제 작업 파일을 바꾸지 않는 격리 디렉터리에서 수행한다.

### 필수 검사

- 단위: 상태 전이, 정체 판정, 부모 진행률, 계획 분해, 자산 경로 검증
- 통합: MCP `save_plan`, `record_event`, `record_heartbeat`, `get_state`, 요약·질의 왕복
- 화면 계약: 선택 노드 필터, 차단 작업함, 기간 필터, SSE 갱신, IME 입력
- 펫 UI: 등록·교체·숨김·그래프 전환·상태별 표현·접근성
- 보안: localhost bind, DPAPI 키, 펫 경로 탈출, 실행 파일 업로드 차단, 로그 비밀 마스킹
- 설치: Release/publish 자체검사, stdio protocol·도구 수, 버전·SHA-256, 기존 PID 보존
- 사용자 수용: “지금 무엇이 막혔고 무엇을 해야 하는가”를 한 화면에서 답할 수 있는지 확인

### 릴리스 승인 기준

1. 경고·오류 없는 Release 빌드
2. source·publish 자체검사 통과
3. 기존 기능의 MCP·대시보드 회귀 없음
4. 정체·차단·중단이 서로 다른 상태로 표시됨
5. 펫을 숨겨도 핵심 관제 기능이 완전히 동작함
6. 설치 전후 기존 SMSR 프로세스와 데이터가 불필요하게 사라지지 않음
7. 문서·버전·설치 파일·체크섬이 일치함

결함은 `재현 단계 → 기대 결과 → 실제 결과 → 로그/스크린샷 → 영향도` 순서로 기록하고, 데이터 손실·보안·상태 오판은 우선 수정한다.

## 9. 개발 방법론과 커뮤니케이션

### 방법론

- 단계별 게이트를 통과하는 짧은 수직 슬라이스 방식
- 한 기능은 계약·화면·자체검사·문서까지 묶어 완료
- 기존 구조 재사용과 최소 변경을 우선
- 사용자 승인이 필요한 화면은 구현 전에 HTML 예시 또는 계약으로 확인
- 완료 노드는 다시 열지 않고, 보완 작업은 새 형제 노드로 추가

### 변경 요청 처리

요청을 `핵심 상태`, `사용자 개입`, `표현 개선`, `고도화`, `보류`로 분류한다. 데이터 계약이나 보안에 영향을 주는 변경은 구현 전에 완료 기준과 회귀 범위를 갱신한다.

### 보고 체계

- 작업 시작: 목표·범위·완료 기준
- 의미 있는 변화: 노드 상태·진행률·검증 결과·산출물
- 막힘: 원인·영향·선택지·필요한 사용자 결정
- 완료: 변경 파일·명령·검증·남은 위험·릴리스 자산

개발 이력은 `docs/development-log.md` 형식을 따르고, 원시 사고 과정·프롬프트 원문·비밀은 기록하지 않는다.

### 작업 전달 규칙

- 각 에이전트는 입력 자료와 완료 기준을 먼저 확인한다.
- 실제 파일 변경이 있으면 변경 파일·검증 명령·남은 위험을 기록한다.
- 상태가 바뀐 경우에만 그래프 이벤트를 기록한다.
- 완료된 노드는 수정하지 않고 후속 보완은 새 작업으로 추가한다.
- 에이전트 산출물은 다음 에이전트가 바로 검토할 수 있는 계약, 테스트, 문서 형태로 남긴다.
