WPF MCP 작업 관제 앱 개발 계획서

Windows 전용 로컬 앱으로, AI 에이전트가 MCP로 남긴 작업 이벤트를 저장하고 브라우저 대시보드에서 프로젝트 진행 상황을 확인한다.

최초 설계 이력: 현재 사용법과 MCP 계약은 요청형 그래프 사용 안내와 MCP 연결 문서를 기준으로 한다.

계획 가정과 MVP 성공 지표

  • 1인 개발 기준으로 기능 완료 기준에 맞춰 MVP를 진행한다.
  • 특정 에이전트 제품에 종속하지 않고, 로컬 MCP 클라이언트용 공통 계약만 제공한다.
  • 이벤트 1건이 중복 없이 저장되고 서버 재시작 뒤에도 API와 브라우저에 같은 상태로 표시되면 MVP를 성공으로 본다.

1. 범위와 목표

  • WPF + WPF-UI 기반의 가벼운 Windows 앱
  • 앱에서 로컬 웹서버 시작/중지와 프로젝트 관리
  • 에이전트는 MCP로 작업 이벤트만 기록
  • 대시보드는 기본 브라우저에서 표시
  • 요약은 앱 LLM 옵션 또는 호출 에이전트 fallback

제외 범위: 원격 접속, 클라우드 동기화, 다중 사용자 권한, 에이전트 실행/중단 제어, WebView 내장 대시보드.

7. 요약과 Export

앱 설정에서 LLM 요약이 켜져 있고 API 키가 있으면 앱이 요약한다. 설정이 없으면 MCP가 요약 재료를 반환하고 호출한 에이전트가 save_summary로 저장한다.

Export는 HTML, Markdown, JSON, ZIP을 지원한다. ZIP에는 dashboard.html, workflow-state.json, events.jsonl, summary.md, artifacts-index.json을 포함한다.

8. 보안 규칙

  • 서버는 127.0.0.1에만 bind
  • local token으로 MCP 호출 검증
  • API key는 DPAPI 또는 Credential Manager에 저장
  • artifact 경로는 프로젝트 root 밖으로 나갈 수 없음
  • HTML 렌더링은 escaping 또는 textContent 사용

9. 개발 단계

Phase목표완료 기준
1MVP 서버와 DBMCP 호출 후 브라우저에 상태 표시
2WPF 앱앱에서 서버와 프로젝트 대시보드 관리
3실시간과 요약SSE 갱신과 summary 저장/표시
4Export와 안정화프로젝트 기록 export 가능

MVP 확정 범위

  • SQLite를 프로젝트·이벤트·상태의 단일 원본으로 사용한다.
  • MCP는 /mcp의 표준 Streamable HTTP 전송으로 record_event, get_state를 제공하고 local token을 검증한다.
  • 서버는 127.0.0.1에만 bind하며 대시보드는 polling한다.
  • /dashboard?projectId=...&workflowId=...는 고정 템플릿으로 최신 노드 상태를 2초마다 표시한다.
  • JSON 파일, SSE, 요약, export, WPF 관리 기능은 MVP 뒤에 추가한다.

10. QA 기준

  • event_id 기준 중복 저장 방지
  • 동시 MCP 호출 시 SQLite 쓰기 충돌 방지
  • 서버 재시작 후 events에서 state 복구
  • SSE 끊김 시 polling fallback
  • export 결과에 summary, state, events 포함
  • artifact path traversal 차단

승인: 빌드 경고·오류가 없고, token 검증 → 저장 → 조회 → 재시작 복구와 브라우저 수용 점검이 재현 가능해야 한다.
