# SMSR Codex 일일 기록과 그래프 추적

기록 분류와 이전 그래프 선택 절차는 [일일 기록과 복잡 작업 그래프 안내](graph-tracking-guide.md)를 참고한다.

SMSR은 에이전트를 호출하지 않는 수동 수신기다. 연결된 Codex 메인 에이전트와 하위 에이전트가 각자의 상태를 SMSR MCP로 전송한다.

## 최초 한 번

1. SMSR을 실행한다.
2. Codex를 한 번 다시 열고 사용자 전역 훅이 새로 표시되는 경우에만 신뢰한다. MCP는 인증창 없는 로컬 stdio 브리지로 자동 연결된다.

이후 연결 설정을 다시 지정할 필요는 없다. SMSR은 실행할 때마다 서버·자동 시작·MCP 설정·전역 훅을 확인하고 누락된 SMSR 항목만 복구한다. 실제 파일 변경은 일일 기록으로 요약하고, 작업 그래프는 사용자가 요청하거나 설정된 복잡도 기준을 만족할 때만 생성한다.

## 자동 분류 동작

- `UserPromptSubmit` 훅은 프로젝트 폴더명과 현재 task/session ID를 추가 개발자 컨텍스트로 제공한다. `PostToolUse`, 세션·하위 에이전트·턴 lifecycle 훅은 활성 그래프가 있을 때만 정규화된 활동을 `activity.jsonl`에 기록한다. 위임 작업의 원본·부모 task ID는 새 workflow에 사용하지 않는다.
- 계산·짧은 검색·질문·상태 확인처럼 프로젝트 파일을 바꾸지 않은 작업은 기록하지 않는다.
- 실제 파일 변경은 완료 전에 `record_daily_activity`로 제목·요약·변경 파일·검증 결과를 한 번 기록한다.
- 설정의 자동 그래프가 켜져 있고 복잡도 신호를 두 개 이상 만족하거나 사용자가 그래프를 명시적으로 요청하면 에이전트가 `save_plan`, `record_heartbeat`, `record_event`도 호출한다.
- 이전 그래프를 이어 달라고 요청하면 `list_workflows`로 찾고 선택한 그래프를 `get_plan`·`get_state`로 불러온다.
- 요청한 작업이 완료·실패·중단될 때까지 관련 후속 작업을 같은 그래프에 갱신하고, 최종 상태 이후에는 heartbeat와 그래프 갱신을 끝낸다.
- 활성 그래프의 계획이 바뀌면 같은 workflow ID로 `save_plan`을 다시 호출해 순서와 새 노드를 반영한다.
- 같은 Codex 세션에서 다른 프로젝트나 새 그래프로 전환하면 새 추적 도구 호출의 project·workflow ID가 기존 활동 세션 매핑을 즉시 교체한다.
- `SUCCESS(100%)` 노드는 완료 기록으로 유지한다. 같은 요청의 후속 작업은 실행 전에 새 형제·최상위 노드로 추가하고 완료 노드와 `dependsOn`으로 연결한다. 목적이 다른 요청은 독립적으로 복잡도 기준을 만족하거나 명시 요청된 경우에만 workflow ID를 생략해 새 그래프로 시작한다.

훅 명령은 사용자 프롬프트 원문을 출력하거나 SMSR에 저장하지 않는다. 비밀, 원시 명령, 도구 입력·출력도 저장하지 않고 이벤트 분류와 도구 이름만 추적한다. SMSR 서버가 잠시 없으면 JSONL에 직접 추가하며 훅 오류는 Codex 작업을 차단하지 않는다.

## 다른 컴퓨터

SMSR을 실행하면 같은 폴더에 콘솔용 `SMSR.Bridge.exe`가 준비되고 그 컴퓨터의 실제 브리지 경로와 DPAPI 토큰으로 설정이 자동 생성된다. 브리지는 서버가 없을 때 GUI `SMSR.App.exe`를 백그라운드로 복구한다. 전역 훅 정의가 새로 표시되는 경우에만 신뢰하며 OAuth, 공개 플러그인이나 마켓플레이스 설치는 없다.
