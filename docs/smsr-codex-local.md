# SMSR Codex 요청형 그래프 추적

사용자 요청 예시와 이전 그래프 선택 절차는 [요청형 그래프 사용 안내](graph-tracking-guide.md)를 참고한다.

SMSR은 에이전트를 호출하지 않는 수동 수신기다. 연결된 Codex 메인 에이전트와 하위 에이전트가 각자의 상태를 SMSR MCP로 전송한다.

## 최초 한 번

1. SMSR을 실행한다.
2. Codex를 다시 열고 OAuth 인증과 사용자 전역 훅을 한 번 신뢰한다.

이후 연결 설정을 다시 지정할 필요는 없다. SMSR은 실행할 때마다 서버·자동 시작·MCP 설정·전역 훅을 확인하고 누락된 SMSR 항목만 복구한다. 작업 그래프는 사용자가 해당 작업을 그래프로 추적해 달라고 요청했을 때만 생성한다.

## 요청형 동작

- `UserPromptSubmit` 훅은 프로젝트 폴더명과 현재 task/session ID를 추가 개발자 컨텍스트로 제공한다. `PostToolUse`, 세션·하위 에이전트·턴 lifecycle 훅은 활성 그래프가 있을 때만 정규화된 활동을 `activity.jsonl`에 기록한다. 위임 작업의 원본·부모 task ID는 새 workflow에 사용하지 않는다.
- 일반 작업은 SMSR에 아무 기록도 만들지 않는다.
- 사용자가 그래프·흐름·대시보드·SMSR 워크플로우 추적을 명시적으로 요청하면 에이전트가 `save_plan`, `record_heartbeat`, `record_event`를 호출한다.
- 이전 그래프를 이어 달라고 요청하면 `list_workflows`로 찾고 선택한 그래프를 `get_plan`·`get_state`로 불러온다.
- 요청한 작업이 완료·실패·중단될 때까지 관련 후속 작업을 같은 그래프에 갱신하고, 최종 상태 이후에는 heartbeat와 그래프 갱신을 끝낸다.
- 완료된 그래프에 이후의 무관한 요청을 추가하지 않는다.

훅 명령은 사용자 프롬프트 원문을 출력하거나 SMSR에 저장하지 않는다. 비밀, 원시 명령, 도구 입력·출력도 저장하지 않고 이벤트 분류와 도구 이름만 추적한다. SMSR 서버가 잠시 없으면 JSONL에 직접 추가하며 훅 오류는 Codex 작업을 차단하지 않는다.

## 다른 컴퓨터

SMSR을 실행하면 그 컴퓨터의 실행 경로로 설정이 자동 생성된다. 최초 OAuth와 전역 훅 신뢰만 다시 수행한다. 공개 플러그인이나 마켓플레이스 설치는 없다.
