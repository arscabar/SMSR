1. 목표·범위·제외 범위

목표

  • 코드·문서·미디어를 파일 목록뿐 아니라 근거 있는 지식과 관계로 색인합니다.
  • 질문·구성요소 설명·변경 영향·구조 보고서를 SMSR 전용 스킬과 기존 MCP 도구로 제공합니다.
  • 대형 그래프는 의미 있는 그룹으로 요약하고, 필요한 상세 관계와 원문으로 이동합니다.
  • 변경·삭제·실패·갱신·피드백이 다음 분석에 반영되도록 관리합니다.

구현 범위

요청한 14개 항목 모두를 포함합니다. 언어별 구조 분석은 F0에서 고정한 Graphify 버전의 지원 목록을 기준으로 확장하고, 언어·확장자·프레임워크별 실제 지원 등급을 공개합니다. PDF·DOCX·XLSX, 이미지·음원·영상은 변환·추출·관계 저장·조회·근거 화면까지 연결합니다. 스킬도 문서 파일 생성만으로 완료 처리하지 않고 실제 호출 경로를 검증합니다.

보존할 구현과 사용자 결정

  • 기존 색인·검색·경로·영향·리비전·본문 벡터 검색·읽기 전용 Cypher·심층 결과 통합·부분 재분석·DPAPI 캐시를 재사용합니다.
  • SQLite를 기본 저장소로 유지합니다. 전용 그래프 DB 교체 여부는 같은 데이터와 질의로 성능을 실측한 뒤 별도로 결정합니다.
  • 원문 질문·프롬프트 로그는 저장하지 않습니다. 학습 기록은 동의된 구조화된 요약·노드 ID·결과 등급만 사용합니다.
  • 전역 Git/Codex 훅 설치는 검사·설치·복구 기능까지만 구현합니다. 사용자 전역 설정은 별도 승인 없이 변경하지 않습니다.
  • 저장소 간 확정 연결은 명시적 파일/프로젝트 참조만 허용합니다. 같은 이름이나 의미 유사도만으로 실제 호출·참조를 확정하지 않습니다.
  • 찾기 한 화면에서 검색·관계·원문 탐색을 유지합니다. 기존에 제거한 중복 메뉴, 문서 제목 범례, 불필요한 기술 설명을 다시 노출하지 않습니다.

제외 범위

전 언어 컴파일러 수준의 판정, 실제 실행 순서 보장, 정밀 alias/taint/PDG, 자동 공개 게시, 무승인 외부 데이터 전송·전역 설정 변경, Neo4j/FalkorDB 운영 서버 구축·자동 push, 기존 기록의 결과 추정 복원은 포함하지 않습니다. WPF 전용 기능으로 범위를 한정하지 않습니다. 필요한 보안·입력 검증·접근성은 제외하지 않습니다.

5. 검증·완료 판정·위험 관리

완료의 의미

  • 각 leaf는 표의 결과와 연결된 검사가 성공해야 SUCCESS. 코드 복사·스킬 파일 생성·파일 색인만으로 전체 완료 처리 금지.
  • 언어별 통과는 F0 고정 지원 범위의 정답/원본 대조 기준입니다. 원본에 없는 동적 해소·실행 의미를 성공률에 섞지 않습니다.
  • 정적 관계·모델 추론·학습 선호를 별도로 저장/표시하고, 근거 없는 결과는 AMBIGUOUS 또는 미확인.
  • 최종 완료는 R01~R14의 필수 검사 모두 통과와 전체 원본 소스 빌드·실제 실행본 검증. 일부 기능만 제외한 임시 빌드는 전체 인수의 대체 근거로 사용하지 않음.
  • 기존 자료의 백업·삭제/실패 보호·외부 경로·비밀값·XSS·무승인 전송/설정 변경 검사도 필수.

성능 측정

냉/온 캐시, 자료 수·총 바이트·지원/제외 파일·노드/관계·관계 종류·시스템 자원을 함께 기록합니다. 실제 AO3·SMSR, 기존 5만 노드/20만 관계, 10,000파일·28MiB를 넘는 합성 자료로 전체/증분 색인 시간·peak 메모리·취소 반응·질의 p50/p95·UI 응답을 측정합니다. F0에서 고정한 기존 기준 대비 구조 질의 p95가 20% 이상 악화하면 원인 검토를 수행하고, 약속할 수 없는 상한은 완료 보고에 공개합니다. 정적 질의와 외부 모델 대기 시간을 분리합니다.

작업 이력

승인 후 구현 그래프는 페이즈를 parent, 표의 42개 작업을 leaf로 작성합니다. 선행 SUCCESS 후 후행 착수, 관련 추가 작업은 완료 노드를 재개하지 않고 새 sibling으로 연결합니다. 시작 때 요청 요약, 의미 있는 진행·검증·실패 때 event, 조용한 활성 작업만 heartbeat, 최종 실제 result·산출물·남은 위험을 기록합니다. 작업별 날짜 이력과 요청당 1개 daily activity를 남깁니다. 원문 질문·raw command·tool input/output·사고 과정은 기록하지 않습니다.

반복 실패·중단 규칙

같은 원인으로 3회 실패하면 즉시 재시도를 중단하고 원인·시도 요약·새 계획·필요한 결정을 기록합니다. 조건 부족은 BLOCKED, 실제 실패는 FAILED, 작업 중단/요청 전환은 CANCELLED. 부모는 필수 자식과 검증이 성공했을 때만 완료됩니다. 조용히 누락시키거나 실패한 입력을 처리 완료로 표시하지 않습니다.
