제공된 코드에서 callbacks()는 기존 캐시 읽기·저장 함수를 보관하고, 파일 캐시 처리와 통계를 덧붙이는 load·save 콜백 및 활성 캐시 이름 집합을 반환하는 구성 함수로 해석된다. 콜백이 실제로 등록되거나 실행되는 외부 코드는 제시되지 않았다.

동작 · 추정

entry()는 root 기준 상대 경로의 SHA-256 해시로 .bin 파일 이름을 만들고 active에 추가한다. cache.file_hash()의 결과로 .json 경로를 구성하여 두 경로를 반환한다. checked()의 내부 검증 방식은 이 근거만으로 알 수 없다.

동작 · 추정

load()는 임시 파일이 없고 영속 파일이 있을 때 복원을 시도한다. 16 MiB를 초과하면 ValueError를 발생시키고, protect() 반환값을 줄바꿈으로 나눈 뒤 digest가 임시 파일의 stem과 같을 때 payload를 기록한다. 이 처리에서 OSError 또는 ValueError가 발생하면 corrupt 통계를 증가시킨다.

동작 · 추정

load()는 기존 읽기 함수의 반환값을 그대로 반환한다. 각 path를 처음 처리할 때만 반환값의 참·거짓에 따라 hits 또는 misses를 증가시킨다.

동작 · 추정

save()는 기존 저장 함수를 호출한 뒤, 임시 파일이 존재하고 크기가 16 MiB 이하이면 stem·줄바꿈·파일 내용을 protect()에 전달한다. 그 결과를 .tmp 파일에 기록하고 영속 파일 경로로 교체한다. protect()의 구체적인 구현은 제공되지 않았다.
