## 1. 범위와 목표

### 배경·문제

SMSR은 SQLite의 `plan_nodes`, `events`, `current_state`, `workflow_context`로 작업 계획·실행 상태·배경·방식·결과를 기록한다. 계획 당시에는 작업 이력과 코드·문서 근거를 한 경로로 확인하기 어려웠다. 현재 하위 작업 완료·의존성 검사, P0 계획 버전·타임라인, P1 파일·Markdown 관계 색인과 조회를 구현했고 최신 publish 실행본의 실제 관계 화면과 운영 DB 사본 복원도 확인했다. 별도 PC 설치·전체 스크린리더/IME·사용자 출시 수용은 남아 있으며 과거 기록의 누락된 결과는 추정 복원하지 않는다.

### 사용자·성공 기준

주 사용자는 로컬 Windows에서 Codex 작업을 관제하는 개발자와 인수인계·감사를 하는 검토자다. 목표는 (1) 선택한 작업의 이유·계획 버전·실행 순서·증거·결과를 화면과 내보내기에서 재현하고, (2) 변경 파일/심벌에서 직접·간접 영향과 근거 경로를 조회하며, (3) 근거가 없거나 오래된 관계를 확정 사실로 표시하지 않는 것이다.

| 측정 지표 | 출시 승인 기준(초기 목표) |
|---|---|
| 이력 무결성 | 이벤트 중복·재시작·계획 수정 테스트에서 손실 0건; 계획/실행/결과 링크의 고아 참조 0건 |
| 작업 상태 | 부모 `SUCCESS`는 필수 하위 노드·선행 노드가 `SUCCESS`일 때만 허용; 구기록 불일치는 진단으로 표시 |
| 관계 정확도 | 검토용 표본에서 확정 관계의 정밀도 ≥90%; 문법에서 읽은 참조와 실제 구현까지 해소한 관계를 구분하고, 추론·모호·오래됨을 별도 표시 |
| 조회 성능 | 가정된 파일 5천/노드 5만/간선 20만 규모에서 대표 경로·영향 조회 p95 ≤2초; 색인 중 UI 응답 유지 |

## 2. 구조·데이터·화면 계약

**저장 원칙.** `events`는 실행 사실의 원본, `plan_nodes`는 최신 계획, `workflow_context`는 사용자가 명시한 이유·방식·결과, `current_state`는 조회용 투영이다. 새 `plan_revisions`·`plan_revision_nodes`에 계획 저장 시점의 전체 스냅샷과 작성 시각·변경 사유를 트랜잭션으로 보존한다. 이미 지난 계획은 현재 값으로 역산하지 않는다. 기존 기록은 `버전 이력 없음`으로 표시한다.

**관계 색인.** `graph_nodes`(프로젝트, 그래프 종류, 안정 키, 종류, 제목, 소스 경로/리비전/해시, 메타데이터)와 `graph_edges`(출발/도착 키, 관계 종류, 원천, 확신도, 해소 상태, 근거 이벤트/파일/범위, 색인 버전)를 SQLite에 둔다. 작업 노드·이벤트는 기존 원본을 참조하는 재생성 가능한 투영으로, 코드·문서는 허용 경로의 색인으로 다룬다. 별도 `workflow_evidence_links`로 작업↔파일/심벌/문서/검증 산출물을 연결한다. 안정 키는 프로젝트·상대 경로·심벌 범위를 포함하고 한국어/대소문자 정규화 충돌을 시험한다. 파일별 소유 노드·간선을 기록해 변경 시 해당 부분만 교체하고, 삭제·제외된 파일의 관계는 제거한다. 이전 색인과 새 색인은 트랜잭션 안에서 검증한 뒤 교체하며 고아 간선·중복·자가 연결·예상 밖의 대량 축소를 진단한다.

**분석 범위.** P1 공통 코어는 파일, Markdown 제목·로컬 링크·코드 인용, 명시적 작업 산출물 연결이다. 문서의 `경로::심벌`은 심벌 색인이 있는 경우 해당 파일의 유일한 대상일 때만, 이름만 있는 심벌은 전체 색인에서 유일하고 소유 관계가 맞을 때만 연결한다. 심벌 색인이 없는 언어는 파일 관계까지만 확정하고 심벌 인용은 미해소로 남긴다. 중복 이름·범위 밖 상대 경로도 억지로 연결하지 않는다. 언어별 호출·바인딩·프로젝트 파일 분석은 선택형 분석기로 분리한다. SMSR 자체가 WPF라는 이유로 다른 프로젝트의 색인을 WPF에 한정하지 않는다. .NET/WPF 분석기는 대상 프로젝트가 해당 기술을 쓰고 정답집에서 관계 정확도를 입증할 때 채택한다. 정규식·XAML 바인딩 문자열만으로 실제 C# 구현을 `확정`이라 표시하지 않으며, 필요 시 Roslyn 또는 검증된 분석기 도입을 결정한다. 외부/생성/바이너리/비밀 파일은 기본 제외하고 `.gitignore`와 경로 허용 목록을 존중한다.

**조회.** 노드 맥락, 두 노드 사이 근거 경로, 역방향 영향, 계획 대비 실제 타임라인, 관계 건강도를 기존 MCP/HTTP에 읽기 기능으로 제공한다. 동명 심벌은 경로로 구별하고, 연결이 모호하면 후보를 보여주되 단정하지 않는다. SQLite 재귀 CTE/인접 인덱스와 깊이·노드 수·시간 상한을 사용한다. 순환, 끊어진 링크, 오래된 색인, 출처 없는 추론은 별도 진단한다. 모든 결과에 범위·색인 리비전·간선 방향·근거 위치·확신도·해소 상태·절단 여부를 포함한다. 에이전트는 HTML을 쓰지 않고 이벤트·상태·맥락·증거만 기록한다.

**화면.** 기존 대시보드에 작업 상세의 `이유/방식/결과`, `계획 버전/실행 타임라인`, `연관 코드·문서/영향 경로` 탭을 점진 추가한다. 기존 그래프의 `미기록`과 `기록 없음`을 구분하며, 확정/추론/모호·오래됨을 색상 외 텍스트로 표시한다. 경로 클릭은 근거 파일·이벤트로 이동하고, 검색·필터·키보드 탐색·한국어 IME를 검증한다.

**보안·운영.** Kestrel은 기본 `127.0.0.1` 유지. 입력 크기·경로 범위·쿼리 깊이 제한, HTML 인코딩, MCP 조회와 쓰기 권한 분리, 민감 파일/토큰/원시 프롬프트 색인 금지. 정적 MCP/API 선언 지도에는 경로·도구 이름만 보관하고 값·인수·토큰은 저장하지 않는다. 원문 질문 로그는 제외한다. 전역 Git 훅은 설치 기능만 제공하고 실제 사용자 설정에는 적용하지 않는다. 비밀이 필요하면 DPAPI/Credential Manager를 사용한다. DB 마이그레이션 전 백업, 실패 시 트랜잭션 롤백, 색인 손상 시 원본에서 재구축한다. 전용 그래프 DB는 실제 워크로드에서 SQLite 목표를 반복 초과하고 인덱스/쿼리 최적화가 실패할 때만 재검토한다.

**P2 개별 채택 게이트.** 언어 분석기는 대상 저장소의 언어와 정답집을 먼저 확정하고 공통 노드·간선 계약으로 결과를 내보낸다. .NET/WPF의 `.slnx`·`.csproj`·XAML 분석은 가능한 선택지일 뿐 SMSR 전체의 기본 분석 범위가 아니다. 그래프 차이는 같은 프로젝트의 두 리비전을 비교하고 추가·삭제·변경 근거를 보존한다. 조회 피드백은 `유용/오류/수정됨` 같은 구조화된 판정과 대상 관계·시각·출처 해시만 기록하며 원문 질문/응답을 저장하지 않는다. 소스가 바뀐 피드백은 오래됨으로 처리한다. MCP/API 경로 지도는 비밀값을 제외한 구성·호출 관계의 정확도 표본을 통과해야 켠다. 커뮤니티 축약은 화면의 노드 수·응답 지연이 실제 한계를 넘을 때, 크로스 저장소 결합은 여러 저장소의 동일 심벌이 충돌하지 않는 식별·권한 설계가 승인될 때만 별도 착수한다.

## 4. 일정과 마일스톤

아래는 착수 시 위험을 포함한 예상 일정의 이력이다. 현재 남은 개발 기간을 뜻하지 않는다. 2026-09-28 기준 P1 기능·개발자 검증은 완료됐고, 사용자 출시 수용과 P2 미구현 항목을 별도로 관리한다.

**P0 수용 잔여 작업과 P1 공통 코어 기준 5주(약 25영업일), 위험 버퍼 포함 5–7주.** 앞선 4주 추정에 문서→코드 해소, 파일 소유권 증분 갱신, 무결성·출처 구분 수용 검사를 추가해 1주를 늘렸다. Codex가 변경·자체검사·문서화를 연속 수행하고, 사용자 결정은 요청 후 1영업일 안에 받으며, 기존 개발/설치 환경이 작동한다는 전제다. 중단 없는 자율 실행을 보장한다는 뜻은 아니다.

P1은 특정 언어의 호출 그래프까지 완성한다는 약속이 아니다. 언어별 분석기, 그래프 diff·피드백·MCP 구성 관계는 4주차 게이트에서 각각 채택 여부를 결정하고, 선택한 P2 묶음에 **별도 5–15영업일**을 산정한다. 예상 밖의 DB 이전·설치본 결함은 기본 버퍼에서 처리하되, 7주를 넘기면 P2를 이월하고 원인·새 일정을 승인받는다. 성능 미달 시 범위를 줄이기 전 SQLite 인덱스·쿼리를 먼저 측정·개선한다. P2와 보류 항목은 5주 기본 납품 범위가 아니다.

## 5. 자원과 예산

기존의 **6 M/M·인건비 5,280만–8,280만원 추정은 폐기**한다. 대체 자원은 Codex 실행 25영업일(버퍼 10영업일), 사용자 승인·수용검사 약 5–10시간(주당 1–2시간)이다. 이는 사람의 M/M으로 환산하지 않는다. 추가 채용비와 필수 외부 API/SaaS 비용은 0원 가정이다. 총 추가 비용은 **실제 Codex 사용료 + 사용자 검수 시간의 내부 기회비용 + 선택적 백업/코드서명 비용**으로 계산한다. 사용량 요금·사용자 시간 단가를 모르므로 원화 총액을 꾸며내지 않고 1주차 실측 사용량×5–7주에 30% 여유를 더해 재산정한다. 기존 Windows PC·.NET 8/WPF-UI/SQLite/Kestrel·Git·자체검사를 재사용한다. Graphify Python 실행 환경 또는 Roslyn 패키지는 대상 언어·정확도·운영 부담을 비교한 후 선택하며 기본 의존성으로 추가하지 않는다.

## 7. QA·릴리스 승인

단위 시험은 계획 버전, 부모/의존성 상태, 안정 키·간선 유일성·순환·경로 제한을 다룬다. 문서 인용은 상대/절대 경로, 동명 심벌, 범위 밖 경로, 심벌 색인 부재를 포함하고, 명시적 참조와 실제 구현 해소를 분리해 검증한다. 통합 시험은 MCP/HTTP→SQLite→WPF/브라우저, 재시작·중복 이벤트·마이그레이션·백업 복원과 파일별 관계 교체·삭제·제외·롤백·대량 축소 차단을 확인한다. E2E에는 실제 부모 `SUCCESS`/자식 0% 구기록, 신규 정상 흐름, 이유·결과 미기록/입력/수정, 파일 변경·삭제·이름 변경, 깨진 Markdown 링크를 넣는다. 선택형 언어 분석기는 해당 언어의 별도 정답집을 통과해야 켠다. 성능은 1주차 고정 표본에서 색인 시간·DB 증가량·p95 조회·UI 응답을 측정한다. 보안은 경로 탈출·HTML 삽입·대용량 입력·비밀 파일과 MCP 토큰 값 누출·MCP 쓰기 권한을 시험한다. 접근성은 키보드, 스크린리더 이름, 색상 외 상태 표시, 한국어 IME를 점검한다.

P0 결함·데이터 손실·비밀 노출 0건, 상단 성공 지표 충족, Release 빌드/자체검사/설치본 smoke/복원 테스트 통과가 릴리스 조건이다. 결함은 재현 데이터·기대/실제·심각도·담당·재시험 결과를 기록한다. 같은 원인의 실패가 3회 반복되면 재시도 중지, 원인·시도·새 계획을 개발 로그 또는 이슈에 남긴다.

## 8. 개발 방법과 소통

1주 단위 게이트에서 수직 기능 한 조각(저장→조회→화면→검증)을 끝낸다. 백로그는 P0/P1/P2와 명시적 제외 목록으로 관리하고, 범위 변경은 정확도·일정·데이터 이전 영향 및 승인자를 기록한다. Codex는 작업 중 의미 있는 상태 변화를 SMSR에 기록하고, 사용자는 주 1회 데모·위험·결정 항목을 검토하며, 릴리스 전 수용검사를 한다. SMSR 작업 그래프에는 계획·상태·증거만, `docs/development-log.md`에는 변경 파일/사유/명령/검증/위험/다음 조치를 기록한다. 원시 사고 과정·비밀·프롬프트 원문은 남기지 않는다. 데이터 손실/비밀 노출/P0 결함은 즉시 중단·보고, 1영업일 내 복구·범위 재결정한다.

## 결정 대기·참고

- 확인 필요: 시작일, 사용자 게이트 응답 가능 시간, 사용량 예산 상한, 색인 대상 저장소·언어, 민감 경로 정책, 코드서명 필요 여부. 답이 없으면 P1은 언어 공통 범위로 진행하고 1주차에 나머지를 확정한다.
- 이전 로드맵의 `지식 그래프 보류`는 당시 범위였다. 이 계획은 사용자의 신규 범위 결정이며 구현 시작 시 로드맵을 갱신한다.
- 현행 소스 기준 `workflow_context`는 아직 배포본에서 검증하지 않았다. 1주차에 설치본과 소스 기능을 대조한다.
