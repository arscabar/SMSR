# 요청형 그래프 사용 안내

SMSR은 일반 Codex 작업을 기록하지 않는다. 사용자가 그래프 추적을 명시적으로 요청한 범위에만 계획, 에이전트 heartbeat, 진행 상태와 산출물을 저장한다.

## 새 그래프 시작

```text
이 작업을 SMSR 그래프로 추적하면서 구현하고 검증해줘.
```

에이전트는 저장소 폴더명을 `projectId`로 사용하고 현재 Codex task를 기반으로 안정적인 `workflowId`를 정한다. `save_plan`으로 그래프를 만든 뒤 의미 있는 상태 변화만 기록한다.

## 추적 종료

관련 후속 요청은 그래프의 모든 노드가 마무리될 때까지 같은 workflow를 사용한다. 최종 상태는 `SUCCESS`, `FAILED`, `BLOCKED` 중 하나이며 마지막 이벤트 후 heartbeat를 중단한다. 이후의 무관한 요청은 완료된 그래프에 추가하지 않는다.

## 이전 그래프 불러오기

```text
SMSR에서 이 프로젝트의 이전 그래프 목록을 보여줘.
```

에이전트는 `list_workflows(projectId)`로 최근 그래프의 workflow ID, 노드 수, `ACTIVE`·`TERMINAL` 상태와 마지막 활동 시각을 조회한다. 사용할 항목을 정한 뒤 다음처럼 요청한다.

```text
workflowId가 sample-build인 그래프를 불러와 이어서 추적해줘.
```

선택된 그래프는 `get_plan`과 `get_state`로 불러오며 기존 workflow ID를 그대로 사용한다. 후보가 여러 개인데 지칭이 모호하면 에이전트가 임의로 새 그래프를 만들지 않고 선택을 요청한다.

## 기록하지 않는 정보

- 그래프를 요청하지 않은 일반 작업과 질문
- 사용자 프롬프트 원문
- 비밀, 토큰, 원시 셸 명령
- 모든 도구 호출의 세부 내역

전역 `UserPromptSubmit` 훅은 프로젝트와 task 식별자를 에이전트 컨텍스트에만 제공하며 SMSR DB에 lifecycle 활동을 저장하지 않는다.
