# 일일 기록과 복잡 작업 그래프 안내

SMSR은 작업의 크기에 따라 기록 방식을 나눈다.

- 계산, 짧은 검색, 질문·답변, 상태 확인, 탐색처럼 프로젝트 파일을 바꾸지 않은 작업은 기록하지 않는다.
- 실제 파일을 바꾼 간단한 작업은 `record_daily_activity`로 제목, 요약, 변경 파일과 검증 결과만 일일 기록에 남긴다.
- 여러 단계·파일·구성요소·검증이 얽힌 복잡 작업은 설정의 `복잡한 프로젝트 작업을 자동으로 그래프로 추적`이 켜져 있거나 사용자가 그래프를 명시적으로 요청했을 때 그래프와 일일 기록에 함께 남긴다.

자동 그래프는 실제 파일 변경이 있고, 3개 이상의 실행 단계, 여러 파일·구성요소, 빌드·테스트·배포, 병렬 에이전트, 10분 이상의 작업 중 두 가지 이상이 예상될 때만 사용한다. 애매하거나 한 위치의 작은 수정은 일일 기록만 사용한다.

## P1 코드·문서 관계 색인

요구사항별 구현 상태·시험 명령·성능·남은 검수는 [P1 구현·검증 보고서](p1-acceptance-2026-09-28.md)를 참고한다.

웹 메뉴의 `찾기`에서 색인 범위를 열고 `프로젝트 전체` 또는 최상위 폴더 목록을 선택해 `색인 시작`을 누른다. 기존 색인 경로를 재사용하며, 미색인 프로젝트는 앱 저장소와 같은 상위 폴더에서 이름이 정확히 일치하는 Git 폴더를 찾는다. 찾지 못하면 상세 관계 도구에서 처음 한 번 경로를 연결한다. 선택한 폴더는 기존 색인 범위를 대체하고, 이후 최신성 검사에도 유지된다. 첫 색인 뒤에는 `찾기`에서 파일·Markdown 제목을 검색하고, 노드를 선택해 연결 관계와 출처 위치를 확인한다. 상세 도구에서는 역방향 영향과 방향을 지키는 경로를 찾을 수 있다. 작업 그래프에서 들어오면 `record_event.artifacts`에 남긴 정확한 파일 경로와 색인 파일의 연결도 표시한다.

대상은 Git이 추적하거나 무시하지 않는 파일 중 지원 확장자이며, 비밀·생성 디렉터리와 설정 키 파일은 기본 제외한다. 원문 코드·문서 본문은 SQLite에 저장하지 않고 파일 경로·해시·문서 제목·관계 근거 위치만 저장한다. Markdown의 외부 URL은 로컬 관계에서 제외한다. 없는 로컬 파일은 `미해소 참조`로 남기고 같은 이름의 색인 파일을 최대 5개까지 후보로만 보여주며 자동 연결하지 않는다. `경로::심벌` 인용은 심벌 구현을 확인한 관계가 아니라 `FILE_ONLY` 파일 관계로 표시한다. 언어별 호출/바인딩 분석은 P2 선택 항목이다.

재색인은 파일 해시를 비교해 바뀐 파일과 영향을 받는 문서 관계만 교체한다. `현재 소스 확인`은 저장된 해시와 현재 Git 파일을 읽기 전용으로 비교해 추가·변경·삭제를 보여준다. 파일 전체를 읽으므로 명시적으로 누를 때만 실행한다. 동일 위치 중복 참조·자기 파일 참조·고아 관계도 건강도에 표시한다. `순환 관계 검사`는 저장된 방향 관계의 순환 연결 그룹을 요청할 때만 계산하며, 큰 색인은 상한 초과로 판정을 생략한다. 이는 정확한 순환 경로가 아니라 서로 도달 가능한 노드 집합이다. 관계 근거의 `근거 파일 열기`는 색인된 파일 중 현재 해시가 일치하고 크기·경로·바이너리 제한을 통과한 파일의 해당 줄 주변만 읽기 전용으로 보여준다. 원문은 DB에 저장하지 않는다. 예기치 않게 노드가 절반 넘게 줄면 기존 색인을 유지하고 명시적으로 `allowLargeReduction`을 지정해야 한다. MCP에서는 `index_project_graph`, `check_graph_freshness`, `search_project_graph`, `get_graph_context`, `find_graph_path`, `get_graph_impact`, `get_graph_cycles`, `get_graph_health`, `get_workflow_graph_evidence`를 사용할 수 있다. `--graph-self-test`로 색인·증분 갱신·롤백·HTTP/MCP 연결을 점검한다.

## 확장 관계 기능

색인 리비전 비교는 저장된 두 버전의 노드·관계 추가·삭제·변경을 보여준다. 이전 버전은 기능 도입 전까지 소급 복원되지 않으며 현재 버전만 기준점으로 보존한다. 관계의 `유용`/`오류` 피드백에는 관계 식별자·시각·출처 해시만 저장하고 질문/응답 원문은 저장하지 않는다. 소스 재색인 뒤 달라진 피드백은 오래됨으로 표시한다. API/MCP 지도는 코드의 정적 선언 경로·도구 이름만 추출하며 동적 경로와 실제 호출 여부를 보장하지 않는다. 검증 누락은 작업 산출물에 대응하는 **구조화된 검증 기록의 부재**만 뜻하며 테스트 미실행을 단정하지 않는다.

선택 노드는 방향·깊이 1~3의 최대 200개 노드/500개 관계를 JSON으로 내보낼 수 있다. 큰 그래프의 커뮤니티 요약은 근사 그룹이며 정확한 모듈 경계가 아니다. 서로 다른 저장소는 모두 SMSR에 색인돼 있을 때 Markdown 로컬 링크와 `.csproj`/`.slnx`의 명시적 프로젝트 파일 참조가 정확히 대상 파일로 해소되는 경우에만 연결한다. 같은 파일명·심벌명만으로는 연결하지 않는다. 이 연결은 재색인 때 갱신되며 미색인·변경 파일의 새 참조는 확정하지 않는다. 저장소가 많으면 재색인 시 전체 저장소 재검사 비용이 증가한다.

설정의 전역 Git 훅 설치·해제 버튼은 기능만 제공하며 현재 사용자의 전역 Git 설정에는 적용하지 않았다. 직접 설치하면 Git `core.hooksPath` 때문에 저장소별 `.git/hooks`가 실행되지 않을 수 있으므로 경고를 확인해야 한다. 사용자 전역 Codex 훅은 기존 앱 연결 설정을 사용한다. 합성 5천 파일·5만 노드·20만 간선의 `--graph-benchmark`에서 SQLite 경로/영향 조회 p95는 각각 73.6/82.5ms(40회)로 초기 2초 목표를 충족했다. 실제 SMSR 첫 색인은 337파일/887노드/592관계에서 1.115초, Cypher 투영 포함 조회 430ms, 최초 벡터 생성 포함 검색 25.992초였다(단일 측정, p95 아님). SQLite를 원본 DB로 유지하며 장기 DB 증가량·대형 실제 저장소는 추가 측정 대상이다.

## 로컬 Cypher·의미 검색·코드 분석

P2 추가 진행: `본문 의미 검색`에서 저장소 상대 파일/폴더 범위를 지정하면 본문 조각의 로컬 벡터와 근거 줄을 검색한다. 빈 범위는 전체이며 최대 1만 조각을 넘으면 범위를 줄여야 한다. 원문·질문은 저장하지 않고 벡터·해시만 캐시한다. 알려진 비밀 패턴 파일은 제외하고 현재 소스 해시가 다르면 재색인을 요구한다. HTTP POST `/api/graph/body-semantic`은 `{projectId,input,scope}`, MCP는 `search_graph_body(projectId,query,scope)`다. [진행 보고서](p2-progress-2026-09-28.md)에 정밀 분석 잔여 작업과 필터·성능 한계를 기록했다.

`찾기 → 고급 분석 도구`에서 사용한다. 설치는 `scripts/install-graph-runtime.ps1`을 명시적으로 실행한다. Python 3.12 가상 환경을 `%LOCALAPPDATA%/SMSR/graph-runtime`에 만들고 공개 패키지와 고정 리비전 다국어 모델을 받는다. 설치 이후 작업은 오프라인으로 실행되며 소스를 외부 서비스에 보내지 않는다. Git 전역 설정도 변경하지 않는다.

- Cypher: Kuzu 0.11.3의 읽기 전용 질의 방언이다. SQLite의 한 리비전을 임시 그래프에 투영하고 삭제한다. `Node(id,label,kind,path,line)`와 `REL(relation,confidence)`를 조회한다. `MATCH`, 집계·필터·경로 등을 제공하되 쓰기·프로시저·외부 파일 접근은 차단하고 순수 함수 허용 목록을 사용한다. 임의 Neo4j 확장/APOC 호환은 아니다. 최대 5만 노드/20만 관계, 출력 200행, 쿼리 5초·프로세스 2분 제한이다. SQLite 교체 또는 영속 그래프 DB 이관이 아니다.
- 의미 검색: `paraphrase-multilingual-MiniLM-L12-v2`의 384차원 임베딩과 코사인 유사도다. 파일 경로·제목·종류만 검색하며 본문 전체 검색은 아니다. 최대 1만 노드, 변경된 메타데이터만 재임베딩하고 SQLite `graph_derived`에 모델·벡터를 저장한다. 질문과 질문 벡터는 저장하지 않는다.
- 코드 분석: 색인된 현재 파일 하나를 지정한다. 16개 Tree-sitter 문법(C#, Python, JS/TS/TSX, Java, Go, Rust, C/C++, Ruby, PHP, Kotlin, Swift, Scala, Lua)을 연결했다. 구문 선언·미해소 호출·함수 내부 보수적 데이터/제어 의존·휴리스틱 taint 경로를 파일 해시·리비전·시각과 저장한다. 원문/문자열 리터럴은 결과에 저장하지 않는다. 파일이 변경되면 저장 결과를 오래됨으로 표시한다.
- 정확도 경계: 문법 지원이 모든 언어의 모든 선언·심벌 해소 지원을 뜻하지 않는다. 8개 언어의 양성 표본, 상수 입력·함수간 격리 음성 표본을 검증했다. 호출 해소, 타입/별칭, 함수간 흐름, 정확한 sanitizer 처리는 미지원이다. 흐름은 순서 비민감 MAY_DEPEND이며 완전한 PDG나 취약점 판정이 아니다. 결과가 없다고 안전하다는 뜻이 아니다.

MCP: `query_graph_cypher`, `search_graph_semantic`, `analyze_graph_code`, `get_graph_analysis`. HTTP는 같은 출처의 POST `/api/graph/{cypher,semantic,analyze,analysis}`이며 입력은 `{projectId,input}`이다. 질문/쿼리 원문은 저장하지 않는다. 재현 검증은 `GraphRuntime/test_runtime.py --vectors`, 앱 `--graph-advanced-self-test`, `scripts/verify-graph-backup.py`를 사용한다. 백업 검증은 운영 DB를 덮어쓰지 않고 별도 파일에 복원한다.

의존성·라이선스 근거: [Kuzu](https://github.com/kuzudb/kuzu), [FastEmbed](https://github.com/qdrant/fastembed), [Tree-sitter language pack](https://github.com/xberg-io/tree-sitter-language-pack), [모델](https://huggingface.co/qdrant/paraphrase-multilingual-MiniLM-L12-v2-onnx-Q). 패키지 자체 라이선스 및 포함 문법의 라이선스를 배포 시 함께 확인한다. Kuzu의 유지보수·확장 서버 상태는 장기 운영 위험이며 교체 가능한 조회 투영으로만 사용한다.

## 일일 작업 기록

파일 변경 작업이 끝나기 전에 에이전트는 요청별 고유 `activityId`로 `record_daily_activity`를 호출한다. 같은 카드를 정정할 때 같은 ID로 다시 호출하면 상태·요약·파일·검증이 갱신되므로 중복 카드가 생기지 않는다. 복잡 작업은 `workflowId`도 함께 기록해 캘린더에서 해당 그래프를 열 수 있게 한다.

통합 캘린더는 한 번에 한 달만 날짜 그리드로 표시하며 날짜별 그래프·기록 수를 보여준다. 첫 클릭은 단일 날짜, 두 번째 클릭은 두 날짜 사이 기간을 선택한다. 상단 선택 목록에는 선택 기간에 활동한 프로젝트와 해당 프로젝트의 워크플로우를 작업명으로 표시한다. 상세 그래프·일일 기록 목록은 첫 화면에 중복 표시하지 않고, 선택 기간 또는 오늘 하루의 모든 프로젝트 기록을 같은 화면에서 Gemini로 요약한다. Gemini를 사용할 수 없을 때만 Codex 요청으로 전환한다. 계산이나 잠깐 찾은 내용은 일일 기록에 포함하지 않는다.

## 새 그래프 시작

```text
이 작업을 SMSR 그래프로 추적하면서 구현하고 검증해줘.
```

에이전트는 저장소 폴더명을 `projectId`로 사용하고 새 그래프의 첫 `save_plan`에서는 `workflowId`를 생략한다. SMSR은 `yyyyMMdd-HHmmssfff__프로젝트명__작업명` 형식의 읽기 쉬운 ID를 반환하며 에이전트는 그래프가 끝날 때까지 그 값을 그대로 사용한다. UUID 형태의 Codex task/session ID는 에이전트 식별에만 사용하며 새 workflow ID로 저장하지 않는다. 기존 UUID 워크플로우도 앱 목록과 대시보드에서는 최상위 작업 제목을 함께 표시한다.

그래프의 계획이 바뀌면 에이전트는 같은 `workflowId`로 `save_plan`을 다시 호출한다. 배열 순서가 화면 순서가 되고, 같은 `nodeId`의 상태는 유지되며 새 노드는 `PENDING`으로 추가된다. `SUCCESS(100%)` 노드는 완료 기록으로 고정한다. 같은 요청의 보완·수정·검증·문서·커밋·배포는 완료 노드의 하위 항목으로 덧붙이지 않고 형제 또는 새 최상위 노드로 추가한 뒤 기존 완료 노드와 `dependsOn`으로 연결한다. 모든 노드가 완료된 뒤 발견된 관련 작업도 실제 작업을 시작하기 전에 이 방식으로 먼저 추가한다. 목적이 다른 별도 요청은 첫 `save_plan`에서 `workflowId`를 생략해 새 그래프로 만든다.

새 그래프의 `save_plan`에는 `reason`(작업 이유)과 `approach`(진행 방식)를 요약한다. 계획을 바꿀 때는 `changeReason`을 함께 보내면 그 이유와 당시 전체 노드 구성이 버전별로 보존된다. `get_plan_revisions`는 과거 계획을, `get_workflow_timeline`은 계획 버전·시간순 이벤트·산출물 증거·과거 상태 불일치를 조회한다. 대시보드의 `기록 선택` 슬라이더는 선택한 기록 한 건만 보여준다. 작업 이력의 배경·방식·결과는 해당 항목을 두 번 클릭해 수정하고, 입력란을 벗어나면 DB에 자동 저장한다. 근거가 없는 과거 기록은 자동으로 추측해 채우지 않는다. `record_event.artifacts`의 항목은 이벤트에 연결된 증거로 저장되므로 비밀·원시 명령을 넣지 않는다. 종료 전 `save_workflow_context.result`에 실제 결과를 기록한다.

기존 그래프의 과거 계획은 추정 복원하지 않고 `버전 이력 없음`으로 표시한다. 기존 이벤트의 산출물은 1회 이관하며, 마이그레이션 전 SQLite 백업은 원본 DB 옆에 `.bak-p0-YYYYMMDD-HHMMSSfff`로 남긴다. 내보내기에는 전체 `events.jsonl`과 `plan-revisions.json`·`evidence-links.json`이 포함된다.

계획을 저장하기 전에 모든 리프 작업을 검토한다. 한 작업 안에 각각 진행·중단·실패·완료를 판단할 수 있는 두 개 이상의 실행 결과, 인계 또는 의존 단계가 있으면 포괄적인 A를 리프로 남기지 않고 A를 부모로 두며 `children`에 A1, A2 등의 작업을 넣는다. 서버는 이를 `parentNodeId` 계층으로 저장하고, 대시보드에서 부모 노드를 누르면 해당 하위 워크플로로 들어간다. 단순히 오래 걸린다는 이유만으로 중첩하지 않으며, 각각의 상태와 완료를 독립적으로 추적해야 할 때만 만든다.

계획 저장 직후 첫 실행 노드를 `IN_PROGRESS`로 기록한다. 이 시작 이벤트에는 그래프를 만든 사용자 요청을 `사용자 요청 요약:` 1~2문장으로 남긴다. 활성 그래프에 관련 후속 요청이 들어오면 새 노드를 추가한 뒤 그 요청 요약도 시작 이벤트에 남긴다. 프롬프트 원문·비밀·개인정보는 복사하지 않는다. 이후 노드 시작, 구현 단계 완료, 검증 시작, 재시도, 산출물 생성, 다음 작업 변경, 최종 완료가 발생하는 즉시 `record_event`를 호출한다. 여러 변경을 작업 종료 시 한꺼번에 보내지 않는다. 의미 있는 변화 없이 작업이 길어질 때만 30초 이내 heartbeat로 생존 상태를 보완한다. 서버는 이벤트를 받는 즉시 SSE로 브라우저와 앱을 갱신한다.

그래프가 활성화되면 사용자 전역 Codex 훅이 지원되는 로컬 도구 완료와 에이전트·세션 시작/종료를 자동 감지해 워크플로우별 `activity.jsonl`에 추가한다. 대시보드의 `실시간 활동`은 이 파일을 즉시 표시한다. 그래프가 없는 작업은 JSONL을 만들지 않는다. 활동 파일에는 시각, 세션·턴·에이전트·노드 ID, 이벤트·분류·도구 이름만 저장하며 프롬프트, 명령 원문, 도구 입력·출력은 저장하지 않는다.

SMSR 앱의 통합 캘린더는 모든 프로젝트의 그래프와 일일 기록을 수신 날짜로 묶는다. 날짜를 선택하면 복잡 작업 그래프와 간단 작업 카드를 함께 볼 수 있다. 현재 작업을 보고 있을 때 다른 프로젝트 이벤트가 와도 선택을 강제로 바꾸지 않으며 캘린더만 즉시 갱신한다. 같은 Codex 세션에서 A 프로젝트 뒤 B 프로젝트를 추적해도 새 추적 도구 호출의 명시적 프로젝트·workflow가 세션 매핑을 갱신하므로 활동 JSONL이 A에 잘못 붙지 않는다.

대시보드는 긴 제목과 에이전트 ID를 노드 안에서 축약하고 전체 값은 툴팁과 상세 패널에 표시한다. 드릴다운 화면에는 현재 부모 작업도 기준 노드로 함께 표시하여 부모에서 직계 하위 작업으로 이어지는 선을 유지한다. `SUCCESS` 상태는 진행률 100%로 정규화한다. 우측 상태 기록은 노드별 최신 카드 한 장으로 갱신되며, 카드별 접기와 `전체 접기` 상태는 SSE 갱신 뒤에도 유지된다.

## 추적 종료

이미 알고 있는 검증·문서·커밋·배포 같은 남은 범위까지 계획에 넣기 전에는 마지막 노드를 완료하지 않는다. 관련 후속 요청은 기존 완료 이력을 보존한 채 같은 workflow에 새 노드로 이어 붙인다. 최종 상태는 `SUCCESS`, `FAILED`, `BLOCKED`, `CANCELLED` 중 하나다. 완료하지 않고 다음 요청으로 넘어가거나 사용자가 멈춘 작업은 `CANCELLED(중단)`로 기록하고 마지막 이벤트 후 heartbeat를 중단한다. 이후의 무관한 요청은 완료된 그래프에 추가하지 않는다. 그 작업이 독립적으로 복잡도 기준을 만족하거나 사용자가 요청한 경우에만 새 그래프를 시작한다.

## 이전 그래프 불러오기

```text
SMSR에서 이 프로젝트의 이전 그래프 목록을 보여줘.
```

에이전트는 `list_workflows(projectId)`로 최근 그래프의 workflow ID, 노드 수, `ACTIVE`·`TERMINAL` 상태와 마지막 활동 시각을 조회한다. 사용할 항목을 정한 뒤 다음처럼 요청한다.

```text
workflowId가 sample-build인 그래프를 불러와 이어서 추적해줘.
```

선택된 그래프는 `get_plan`과 `get_state`로 불러오며 기존 workflow ID를 그대로 사용한다. 후보가 여러 개인데 지칭이 모호하면 에이전트가 임의로 새 그래프를 만들지 않고 선택을 요청한다.

## C# 파일 묶음 분석

고급 분석 화면의 `C# 명시적 파일 묶음 분석`은 색인된 상대 경로 목록을 Roslyn으로 분석한다. `analyze_graph_csharp_bundle`과 `get_graph_csharp_bundle`에서도 같은 파일·버전·조건부 심벌 묶음을 사용할 수 있다. 입력 순서는 결과 키에 영향을 주지 않는다. 소스 원문 대신 결과·파일 해시·리비전을 저장하며, 의존 파일 변경은 오래됨으로 표시한다.

이 기능은 실제 csproj 설정·NuGet·생성 코드를 반영하는 전체 프로젝트 분석이 아니다. `BOUND_IN_BUNDLE`은 명시적 입력 묶음 기준이며 가상/delegate·동적 호출과 컴파일 오류는 별도로 표시한다. 사용 예제는 [C# 파일 묶음](../samples/graph-csharp/README.md), 남은 범위는 [P2 보고서](p2-progress-2026-09-28.md)를 참고한다.

C# 묶음 결과의 실행 흐름 상세는 컴파일러 블록·조건·후속 블록·예외 영역을 표시한다. 변수 읽기/쓰기 요약은 해당 본문의 구문 영역 정보이며 실제 실행 순서나 함수 간 데이터 전파 확정은 아니다. 저장된 분석 버전이 이전이면 다시 분석하라는 상태를 표시한다.

`함수 간 인자·반환 연결`에서는 호출별 매개변수 선언 위치와 반환 후보를 확인한다. `입출력 근거 연결`은 실행·값 전파·taint 인증이 아니다. 참조 인자·비동기/iterator/참조 반환·가상/동적/조건부 호출에는 제한이 표시된다. 전체 ID·변환 정보·params 요소 위치는 원자료에서 확인한다.

분석 버전 5의 `실행 흐름 상세`에는 할당 후보 위치와 읽기 위치를 함께 표시한다. 분기 합류나 반복 때문에 한 읽기에 여러 후보가 표시될 수 있으며, 같은 위치의 연결은 서로 다른 반복 회차일 수 있다. 정상 CFG의 함수 내부 기본형·문자열 변수 기준이고 실제 경로 실행이나 taint 인증이 아니다. 예외·참조·캡처 등 미지원 문맥은 `분석 불가`와 이유를 표시한다. 과거 저장 결과는 재분석해야 한다.

버전 6부터 같은 상세 화면에서 조건 블록의 참/거짓 선택과 영향을 받는 블록·근거 줄을 확인한다. 종료로 이어지는 CFG 경로를 기준으로 하며, 반복 조건의 자기 연결은 다음 회차를 제어한다는 뜻이다. 명시적 `throw`는 정상 반환과 별도 경로로 계산한다. 종료 불가 영역·예외 처리·비동기 문맥은 사유를 표시한다. 컴파일러가 확정한 불가능한 간선은 `상수 조건 제외`로 표시하고 데이터/제어 의존 계산에서 제외한다. 그 외 조건의 실제 성립·암묵적 예외·함수 간 실행·taint는 검증하지 않는다.

### C# 값 전달 상세

버전 7의 `실행 흐름 상세` 안에서 `값 전달 상세`를 펼치면 연산 입력, 할당, 도달 정의, 임시 값 도달 정의와 반환·조건·호출 경계를 확인한다. 같은 줄의 읽기와 쓰기도 별도 ID로 구분한다. `미해석 구간 포함`은 호출 결과·힙·수신 객체·사용자 연산자 등에 아직 알려지지 않은 값이 있음을 뜻한다. 해당 입력에서 결과까지의 간선을 임의로 만들지 않으므로 연결 부재가 안전함을 증명하지 않는다. 상수의 실제 값이나 원문은 기록하지 않으며 함수 간 값 전파·taint 인증은 아직 제공하지 않는다.

### C# 호출별 반환 의존

버전 8부터 함수의 `실행 흐름 상세` 안에서 `호출별 반환 의존`을 펼치면 반환에 영향을 줄 수 있는 입력 이름과 해당 호출의 입력 값→결과 값 연결을 확인한다. 같은 함수의 여러 호출은 서로 분리한다. `미확정 반환 영향 포함`에는 외부·가상 호출, 힙/사용자 연산자 및 재귀 값 순환 등이 포함된다. 미확정 상태의 `확인된 입력: 없음`은 무관함이나 안전함을 뜻하지 않는다. 조건의 암묵 흐름·부수 효과·실제 인자 값에 따른 경로 특수화·종료 보장·taint 판정은 제외한다. 내부 값 그래프와 함수 간 요약은 별도 근거이며 구버전 저장 결과는 재분석해야 한다.

### C# 호출 인자 경로

버전 9의 `실행 흐름 상세 → 호출 인자 경로`는 반환값 없는 호출도 포함한다. 각 호출의 인자 순번은 0부터 시작하며, 확인된 입력 이름·값 불확실성·대상 본문 연결 판정을 구분한다. 입력별 상세를 펼치면 읽기/연산/할당/반환 요약을 거쳐 해당 인자에 도달하는 대표 경로 하나를 볼 수 있다. 위치와 값 ID는 호출자 함수 기준이다. `반환 요약 연결`은 대상 함수 내부 경로를 생략한 요약 간선이다. 외부 대상이라고 인자 근원을 모르는 것은 아니며, 인자 근원이 확인됐다고 대상의 실행·보안이 검증된 것도 아니다. 참조/캡처 등 지원하지 않는 함수는 빈 성공 대신 분석 불가 사유를 표시한다. 원자료에는 전체 근거를 저장하며 화면 상세는 앞 100개 인자로 제한한다.

### Java 17 입력 파일 묶음

`그래프 고급 분석 → Java 17 컴파일러 분석`에서 현재 색인된 `.java` 상대 경로를 줄별로 입력하고 분석·저장한다. 직접 호출과 가상 호출의 정적 대상, 인자 순번, 추론 타입, 선언과 진단 위치를 확인할 수 있다. 저장 결과는 동일 파일 묶음의 DB 결과와 원문 변경 여부를 보여준다. 파일 순서는 키에 영향을 주지 않는다. 컴파일 오류 결과는 확정 호출로 승격하지 않으며 메서드 참조는 실행과 구분한다.

기존 JDK 17 이상과 SMSR Java 보조 분석기 클래스가 필요하다. 빌드 방법과 예제는 `samples/graph-java/README.md`를 따른다. 프로젝트 빌드·외부 의존성·processor·대상 코드는 실행하지 않는다. Java CFG/PDG/taint와 실제 런타임 호출 그래프는 미지원이다. 경로·심벌·타입은 저장하지만 원문·상수 값·annotation 값·진단 메시지는 저장하지 않는다.

### Python 컴파일러 근거

기존 `저장소 상대 파일 경로 → 분석·저장`에서 Python 파일을 분석하면 별도의 컴파일러 근거를 표시한다. CPython 3.12의 코드 범위·지역/클로저 슬롯·명령 위치·분기/반복 전이·예외 범위를 확인한다. 외부 클로저 ID는 상위 저장소와 연결된다. 동적 전역/클래스 조회는 확정 대상 ID 없이 표시한다. 생성기/yield 다음 연결은 재개 가능 위치이며 실제 실행을 뜻하지 않는다. 원문·상수 값·진단 원문은 저장하지 않는다. 구문/휴리스틱 분석은 그대로 별도 근거이며 정밀 PDG/taint로 승격하지 않는다. `samples/graph-python/README.md`에 예제가 있다.

### Python 할당·읽기 연결

파일 분석 버전 3의 Python 상세에서 `할당 → 읽기 도달 정의`를 확인한다. 정의 종류·정의/읽기 위치·명령 offset·미할당 후보가 표시된다. 같은 소스 위치라도 컴파일러가 복제한 명령은 별도 근거다. 예외/재개/공유 셀 한계는 부분 상태에 표시하고, 스택 저장·복원 comprehension이나 동적 네임스페이스는 분석 불가 사유를 제공한다. 슬롯 후보 관계는 실제 값·실행 경로·취약점 판정이 아니다. 버전 없는 결과와 버전 2는 재분석해야 한다.

### Python 표현식·호출 인자 연결

파일 분석 버전 4의 함수 상세에는 `입력 → 연산 → 할당·반환·호출 인자` 표가 추가된다. 출발/도착 종류·소스 위치·명령 offset·피연산자 순번을 확인한다. 기존 정의 ID를 그대로 연결하며 분기와 while 반복은 스택 위치별 후보 합집합으로 계산한다. 상수의 값과 이름 인자의 이름은 저장하지 않는다.

`VALUE_FLOW_CANDIDATES`는 모델상 피연산자/할당 후보이지 실제 실행이나 정밀 taint 판정이 아니다. 호출 인자 순번·이름 인자 여부를 표시하지만 호출 결과는 `OPAQUE_CALL_RESULT`로 분리한다. 인자에서 반환값으로 추측 간선을 만들지 않는다. 예외 스택·중단/재개·공유 셀·스택 복원·미지원 명령은 해당 함수 값 그래프를 `UNAVAILABLE`로 표시하고 이유를 남긴다. 기존 슬롯/바이트코드/구문 결과는 보존된다. 버전 없는 결과와 버전 3 이하는 재분석한다.

### Python 반복·메서드 호출

파일 분석 버전 5는 일반 `for`의 반복자→다음 요소→변수 할당, 고정 개수 분해 요소, 속성 조회 및 메서드 수신 객체 후보를 추가한다. 반복 표는 다음 요소와 정상 종료를 구분하며 종료 시 건너뛴 `END_FOR` 위치를 표시한다. 기존 인코딩 전이 표와 값 분석용 정상 전이(`values.transfers`)는 별개다.

메서드 호출의 두 런타임 스택 배치는 값 분석에서 조회 결과+수신 객체 후보로 정규화한다. 수신 객체가 실제 `self`인지, descriptor가 어떤 값을 반환하는지는 확정하지 않는다. 반복자·속성·분해도 사용자 코드를 실행할 수 있는 미해석 프로토콜이다. 호출 인자에서 미해석 호출 반환으로 추측 간선을 만들지 않는다. 실제 대상 코드는 실행하지 않는다. 버전 4 이하 저장 결과는 재분석한다.

## JavaScript·TypeScript·TSX 묶음 분석

- 화면: `/graph/advanced?projectId=SMSR`의 TS/JS 묶음. 예제는 `samples/graph-typescript/README.md`.
- HTTP: `POST /api/graph/typescript`, `/api/graph/typescript-result`; 입력은 `{projectId, paths}`. MCP: `analyze_graph_typescript_bundle`, `get_graph_typescript_bundle`.
- 설치된 Node와 VS Code TypeScript 6.0을 재사용한다. 선택 파일·상대 import·표준 타입만 읽으며 tsconfig·패키지·플러그인·빌드·대상 코드는 실행하지 않는다.
- 선언·참조·오버로드/제네릭 정적 시그니처·위치 인수 대응을 저장한다. TSX·rest/spread 인수 전개는 미지원이다. 런타임 호출 대상·힙/별칭·전체 PDG/taint를 확정하지 않으며 오류가 있으면 `COMPILER_CANDIDATE`다.
- SQLite `graph_derived`의 `typescript` 종류에 버전1·리비전·입력 해시·컴파일러 버전·위치·진단 코드를 저장한다. 원문·리터럴 값·진단 메시지는 제외한다. 원문/색인/분석 버전은 stale 판정하며 컴파일러 변경 후에는 다시 분석해야 한다.
- 최대500파일·개별2 MiB/총16 MiB, 25만 계산/2만 사실, 100초 하위 프로세스/512 MiB Node 힙, 상위2분/16 MiB 출력. 한도 초과는 부분 성공을 저장하지 않는다. 진단 앞200개와 전체 개수 및 타입 요약의 깊이/멤버 제한을 표시한다.

### JS/TS 본문 입출력 연결 (분석 버전2)

같은 묶음의 `functions`는 함수 본문·매개변수·명시 반환 위치, `connections`는 호출별 구현 본문 후보·입력/반환 대응을 담는다. 화면의 **호출별 본문 연결 후보**에서 확인한다. 오버로드 선언과 구현 본문은 다를 수 있다. 중첩 함수의 반환과 서로 다른 호출 결과는 합치지 않는다.

`STATIC_BODY_CANDIDATE`는 실행 대상 확정이 아니다. 기본값은 undefined 조건만 기록하고, 비동기/생성기·생성자/TSX·rest/spread/구조분해·오류/외부 본문은 연결 불가 사유를 표시한다. 함수 내부의 인수→반환 의존성이나 반환 도달 가능성·finally·암묵 반환은 아직 해결하지 않는다. 버전1 저장 결과는 다시 분석해야 한다.

### JS/TS 함수 내부 값 후보 (분석 버전3)

`functions[].values`의 `nodes/edges`를 화면에서 펼쳐 확인한다. 대입의 이전 정의 제거, if·단락·while의 합류를 심벌 ID로 계산한다. `connections`에는 대응하는 인수/본문 매개변수/반환/호출 결과 값 ID가 추가된다. 값 노드가 없는 경우 null이다.

정상 흐름 MAY 모델이며 조건 만족 가능성·예외·heap/alias·연산자 효과·완전한 제어 의존/함수 간 요약을 확정하지 않는다. 외부 호출 인수→반환 간선은 만들지 않는다. 지원하지 않는 구문을 만난 함수는 부분 그래프 대신 `UNAVAILABLE`와 사유를 반환한다. 버전2 이전 결과는 재분석해야 한다.

### JS/TS 반복 전이 (버전4)

for·do/while·break/continue와 증감/복합 대입을 함수 내부 값 후보로 저장한다. continue 이후 for 갱신식은 실행 후보에 포함하고 break 이후에는 제외한다. do 본문에는 0회 경로를 만들지 않는다. 전위/후위 증감은 각각 다음 값/이전 값 노드로 구분한다. 예제의 `counted` 함수를 펼쳐 갱신·도달 정의를 볼 수 있다. 이전 버전3 결과는 재분석이 필요하다. 라벨·for-in/of·switch·예외와 실제 조건 만족성은 아직 지원하지 않는다.

### JS/TS 호출별 반환 요약 (버전5)

본문의 데이터 의존을 함수별 반환 영향 입력 순서(0부터)와 미해석 값 ID로 표시한다. 호출별 파생 간선은 기존 로컬 값 간선과 분리해 저장한다. 다단계·재귀는 고정점으로 계산하며 호출 ID별로 인수/결과를 격리한다. 원문·상수 값은 저장하지 않는다. 버전4 저장 결과는 재분석이 필요하다. 제어 의존·종료·실제 호출 대상·예외·힙 효과는 포함하지 않으므로 영향 입력/미해석 값이 없다는 사실을 보안상 안전으로 해석하지 않는다.

### Java 메서드 값 근거 (버전2)

Java 묶음 분석에 메서드별 값 노드/간선을 저장한다. javac 심벌로 매개변수·지역 변수를 구분하고 대입 GEN/KILL, 분기 합류, while/for/do 고정점, break/continue 및 전후 증감/복합 대입을 처리한다. 한 줄의 다중 변수 선언은 시작·끝 위치를 모두 사용하는 ID로 구분한다. 미지원 구문/컴파일 오류는 해당 메서드의 빈 값 그래프와 사유로 표시한다. 구버전1은 stale이다. 정상 흐름 후보이며 예외·힙/별칭·실제 조건/실행 대상·함수 간 요약·완전한 PDG/taint는 아니다.

### Java 호출별 본문·반환 요약 (버전3)

직접 호출의 javac 대상 심벌과 입력 본문을 대응시키고, 본문 매개변수/반환 값 ID 및 호출 인수/결과 값 ID를 저장한다. 데이터 의존은 다단계/재귀 고정점으로 계산하며 호출별 파생 간선을 기존 로컬 그래프와 분리한다. 가상/가변 호출·외부/미지원 본문은 사유와 미해석 값 ID로 유지한다. 제어 의존·종료·예외·힙/별칭·변환 효과는 포함하지 않는다. 빈 영향/미해석 목록은 안전성이나 완전성을 뜻하지 않는다. Java 버전2는 stale이다.

### Java 정상 CFG·제어 의존 (버전4)

Java 분석의 각 메서드 `control`에 AST 위치·정상 전이·TRUE/FALSE·즉시 후지배·조건별 의존을 저장한다. 단락/삼항, if, while/for/do, 라벨 없는 break/continue, 반환/명시 throw를 처리한다. -1은 합성 종료이며 현재 메서드의 유한 종료 경로만 다룬다. 종료에 도달할 수 없는 영역은 `NON_EXIT_REACHABLE_REGION`과 빈 제어 관계를 반환하되 정상 전이는 표시한다. try/switch/확장 for/라벨/동기화 등 미지원과 컴파일 오류는 빈 CFG·사유를 반환한다. 암묵적 예외·호출 내부 효과·실제 경로 만족성·함수 간 제어/taint는 포함하지 않는다. 기존 값 그래프의 구문상 제어 후보와 별도 표로 구분한다. 버전3 이하 저장 결과는 갱신 필요 상태다.

### Python 정상 경로 제어 의존 (파일 분석 버전6)

Python 함수 상세의 `조건 → 명령 제어 의존`은 컴파일러 명령의 조건별 영향을 표시한다. 정상 전이를 정규화하고 종료 경로 후지배를 계산한다. TRUE/FALSE·NONE/NOT_NONE·반복 다음/소진을 구분하며 명령 위치와 소스 위치를 함께 제공한다. 짧은 반환이 컴파일러에서 복제될 수 있으므로 소스 줄만으로 명령을 합치지 않는다.

예외 범위·생성기/async 중단·종료 불가 영역은 빈 제어 의존과 사유로 표시한다. 반환 및 명시적 raise는 -1 합성 종료로 연결한다. 암묵적 예외·조건 만족성·실제 종료 여부·taint는 포함하지 않는다. 새 근거는 기존 분석 한도/해시/DB/API/MCP를 사용하며 버전5 이하 결과는 재분석한다.

### JS/TS 정상 CFG·제어 의존 (버전8)

함수별 `control`에 컴파일러 AST 위치·정상 전이·분기별 영향·즉시 후지배를 저장한다. 진릿값 TRUE/FALSE와 null 여부 NULLISH/NON_NULLISH를 구분하고 논리 대입의 RHS/대입 실행 조건을 보존한다. 단락/삼항·반복·break/continue·조기 반환의 위치를 공용 제어 표에서 확인한다. switch는 선택식 1회 평가, case 식 검색, CASE_MATCH/CASE_NO_MATCH, 모든 case 불일치 후 default, 본문 fall-through를 보존한다. continue는 switch를 넘어 바깥 반복으로 연결된다. 종료 불가 영역은 제어 관계 없이 사유와 정상 전이를 제공한다. 값 후보와 지원 상태는 독립적이며 제어 표가 존재해도 완전한 값/taint 분석은 아니다. 버전7 이하 stale·원문 제외·해시/삭제 보호는 유지한다.

버전8의 switch 값 분석은 case 검색 중 대입과 본문 진입·fall-through·break·continue를 별도 상태로 합친다. 선택 뒤의 조건식 대입은 앞선 선택 상태에 적용하지 않는다. 함수 간 데이터 요약에도 이 반환 근거를 사용하며 조건 의존은 데이터 영향 입력에서 제외한다. 경로 조건 만족성·예외/힙·실제 호출 대상은 미보장이다. `switchRelayed`의 입력1·2/호출 간선2개와 `switchErased`의 빈 영향 입력을 예제에서 확인한다.

## Python 입력·반환·호출 요약 (파일 분석 버전7)

함수 상세에서 입력 슬롯의 종류와 반환/호출 대상 후보·수신 객체·인자별 데이터 의존 후보를 확인한다. 조건 입력은 데이터 요약에 섞지 않는다. 호출 결과는 미해석 값으로 남기며 함수 간 연결을 추정하지 않는다. 입력 번호는 CPython 슬롯 순서이고 호출 매개변수 바인딩이 아니다. 가변 인자는 컨테이너이며 기본값·이름 인자 이름·원문은 저장하지 않는다. 외부/속성/반복/미할당 경계를 ID로 표시하고, 값 모델 미지원은 요약도 UNAVAILABLE로 표시한다. 빈 영향/미해석 목록은 안전성 증명이 아니다. 버전6 이하 결과는 재분석한다.

## Python 지역 함수 객체 연결 (파일 분석 버전8)

호출 요약에서 `localTarget`의 본문 후보·미확정 후보 포함 여부·연결 불가 사유를 확인한다. 코드 객체→함수 생성→지역 변수 복사로 유일한 후보가 확인되고 위치 인자의 개수/매개변수 종류가 맞을 때 호출별 입출력 위치를 연결한다. 전역 이름 일치·컨테이너/연산 결과는 해소하지 않는다. 여러 후보/외부 값이 섞이면 모호, 가변/이름/생략 인자는 바인딩 미지원이다. 실제 함수 변경과 함수 간 값 전파는 별도 잔여이며 반환 요약은 미해석 상태를 유지한다. 버전7 이하 결과는 stale로 재분석한다.

## Python 호출별 반환 데이터 전파 (파일 분석 버전9)

유일한 지역 본문 후보의 반환에 도달하는 입력만 호출 인자→결과 데이터 간선으로 요약한다. 다단계 호출은 고정점으로 계산하되 호출끼리 입력 라벨을 공유하지 않는다. 바깥 반환과 각 호출 결과 요약의 영향 입력/미해석 값이 함께 갱신된다. 모호/외부/미지원 호출과 본문 내부 미해석은 유지하고 조건 의존은 데이터와 분리한다. 원시 값 노드의 OPAQUE_CALL_RESULT 이름은 유지되므로 최종 상태는 결과 요약으로 확인한다. 버전8 이하 결과는 stale이다. 실제 동적 대상·종료/예외/힙·전체 PDG/taint 판정은 아니다.

## Python 명시적 이름 인자 바인딩 (파일 분석 버전10)

지역 함수의 명시적 위치/이름 인자를 매개변수 슬롯으로 대응시킨다. 위치 전용·이름 전용·혼합 호출을 지원하며 인자 순번과 매개변수 번호가 다를 수 있다. 바인딩 실패는 `bindingReason`에 이름 없는 근거 코드로 표시한다. 중복·누락·모르는 이름·위치 전용 위반에서 데이터 간선을 생성하지 않는다. KW_NAMES 문자열은 메모리에서만 사용하고 결과에는 매개변수 번호/값 ID만 남긴다. 기존 선언 심벌 이름은 유지한다. 생략 기본값·가변 인자·공유셀은 잔여이며 버전9 이하 결과는 stale이다.

## Java switch 식·yield (묶음 분석 버전6)

화살표 결과식과 블록/콜론형 yield를 `SWITCH_ARM_VALUE`/`YIELD`→`SWITCH_RESULT`로 저장한다. 가장 가까운 식별로 결과와 정상 종료 상태를 합류하므로 중첩 yield는 바깥 식을 끝내지 않는다. 조건/반복/중첩 switch 문 안의 yield도 지원한다. 제어 그래프는 식 이후로의 전이, 값 그래프는 결과/지역 대입, 호출 요약은 데이터 입력 의존을 각각 표시한다. 버전5 이하 결과는 갱신 필요다.

예제 `samples/graph-java/Expressions.java`의 pick/relayed는 입력1·2, nested는 덮어쓰기 뒤 입력2, erased는 빈 영향을 보인다. 빈 영향은 안전성 증명이 아니다. try/finally·패턴·힙/별칭·예외·실제 경로 판정·전체16언어 PDG/taint는 잔여다. 명시적 throw와 일치 없는 enum 식은 CFG에서 종료하며 throw의 값 분석은 미지원이다.

## Java switch 문 제어·값 흐름 (묶음 분석 버전5, 이전 이력)

콜론형 본문 이어 실행·화살표형 종료·다중 라벨·중간 default와 라벨 없는 break/continue를 지원한다. CASE_MATCH/CASE_NO_MATCH는 상수 선택을 정규화한 전이이며 case 라벨을 실행하거나 JVM의 실제 비교 순서를 확정한 것이 아니다. 선택식은 한 번 평가한다. 값 표는 본문 대입의 덮어쓰기/합류를, 호출 요약은 그 반환 의존을 반영한다. 버전4 이하 결과는 재분석한다. switch 식/yield·패턴·null/언박싱 예외·경로 만족성·힙/별칭·전체 PDG/taint는 미지원이다. `samples/graph-java/Switches.java`에서 전달과 영향 제거를 비교할 수 있다.

## Java 언어 서버 정의 조회 (제품 연결)

로컬 검색·코드 분석 화면에서 Java 파일 목록·소스 루트·조회할 파일과 위치를 입력한다. 화면은1부터, HTTP/MCP는0부터 시작하는 UTF-16 좌표다. `/api/graph/jdt` 및 `query_graph_java_definition`은 임시 복사본을 분석하고 위치·해시·리비전·프로필을 저장한다. `/api/graph/jdt-result`와 `get_graph_java_definition`은 같은 입력의 저장 결과와 현재 오래됨을 반환한다. 결과 링크는 현재 원문으로 이동한다.

검증된 기본 VS Code Red Hat Java1.56.0 win32-x64 설치만 사용한다. 설치 폴더를 신뢰해야 하며 manifest 확인은 서명 검증이 아니다. 실행 경로/옵션을 API로 받지 않고 원본 설정·빌드·패키지 가져오기를 사용하지 않는다. 알려진 민감 패턴은 복사 전에 거부한다. 후보는 실제 디스패치나 안전성 증명이 아니다. [예제 입력](../samples/graph-jdt/README.md)을 참고한다.

## 실제 Java LSP 프로필 검증 (초기 이력)

`--graph-jdt-self-test <설치된 Java 확장 절대 경로>`는 알려진 임시 Java 프로젝트를 기존 JDT/JRE로 열어 정의3건을 확인한다. 설치 설정을 임시 폴더로 복사하고 자동 빌드/가져오기를 비활성화한다. 공통 원문/리비전/경로/UTF-16 검증과 종료·취소 처리를 재사용한다. 결과는 임시 결과 JSON이며 운영 그래프에 저장하지 않는다.

실제 정의3건과 소스 보존·미빌드 검사를 통과했지만 세션 전체 종료가 느려 공개 HTTP/MCP/UI에는 연결하지 않았다. 임의 저장소에 대한 보안 샌드박스나 전체16언어 의미 정확성·PDG 완료가 아니다. [재현과 잔여 조건](graph-jdt-verification-2026-09-29.md)을 확인한다.
