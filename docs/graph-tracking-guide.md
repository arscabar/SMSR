# 요청형 그래프 사용 안내

SMSR은 일반 Codex 작업을 기록하지 않는다. 사용자가 그래프 추적을 명시적으로 요청한 범위에만 계획, 에이전트 heartbeat, 진행 상태와 산출물을 저장한다.

## 새 그래프 시작

```text
이 작업을 SMSR 그래프로 추적하면서 구현하고 검증해줘.
```

에이전트는 저장소 폴더명을 `projectId`로 사용하고 새 그래프의 첫 `save_plan`에서는 `workflowId`를 생략한다. SMSR은 `yyyyMMdd-HHmmssfff__프로젝트명__작업명` 형식의 읽기 쉬운 ID를 반환하며 에이전트는 그래프가 끝날 때까지 그 값을 그대로 사용한다. UUID 형태의 Codex task/session ID는 에이전트 식별에만 사용하며 새 workflow ID로 저장하지 않는다. 기존 UUID 워크플로우도 앱 목록과 대시보드에서는 최상위 작업 제목을 함께 표시한다.

그래프의 계획이 바뀌면 에이전트는 같은 `workflowId`로 `save_plan`을 다시 호출한다. 배열 순서가 화면 순서가 되고, 같은 `nodeId`의 상태는 유지되며 새 노드는 `PENDING`으로 추가된다. `SUCCESS(100%)` 노드는 완료 기록으로 고정한다. 같은 요청의 보완·수정·검증·문서·커밋·배포는 완료 노드의 하위 항목으로 덧붙이지 않고 형제 또는 새 최상위 노드로 추가한 뒤 기존 완료 노드와 `dependsOn`으로 연결한다. 모든 노드가 완료된 뒤 발견된 관련 작업도 실제 작업을 시작하기 전에 이 방식으로 먼저 추가한다. 목적이 다른 별도 요청은 첫 `save_plan`에서 `workflowId`를 생략해 새 그래프로 만든다.

계획 저장 직후 첫 실행 노드를 `IN_PROGRESS`로 기록한다. 이후 노드 시작, 구현 단계 완료, 검증 시작, 재시도, 산출물 생성, 다음 작업 변경, 최종 완료가 발생하는 즉시 `record_event`를 호출한다. 여러 변경을 작업 종료 시 한꺼번에 보내지 않는다. 의미 있는 변화 없이 작업이 길어질 때만 30초 이내 heartbeat로 생존 상태를 보완한다. 서버는 이벤트를 받는 즉시 SSE로 브라우저와 앱을 갱신한다.

그래프가 활성화되면 사용자 전역 Codex 훅이 지원되는 로컬 도구 완료와 에이전트·세션 시작/종료를 자동 감지해 워크플로우별 `activity.jsonl`에 추가한다. 대시보드의 `실시간 활동`은 이 파일을 즉시 표시한다. 그래프가 없는 일반 작업은 JSONL을 만들지 않는다. 활동 파일에는 시각, 세션·턴·에이전트·노드 ID, 이벤트·분류·도구 이름만 저장하며 프롬프트, 명령 원문, 도구 입력·출력은 저장하지 않는다.

SMSR 앱의 통합 캘린더는 모든 프로젝트를 마지막 수신 날짜로 묶는다. 날짜를 선택하면 그날의 최신 작업으로 전환되고 같은 날짜의 다른 항목도 선택할 수 있다. 현재 작업을 보고 있을 때 다른 프로젝트 이벤트가 와도 선택을 강제로 바꾸지 않으며 캘린더만 즉시 갱신한다. 같은 Codex 세션에서 A 프로젝트 뒤 B 프로젝트를 추적해도 새 추적 도구 호출의 명시적 프로젝트·workflow가 세션 매핑을 갱신하므로 활동 JSONL이 A에 잘못 붙지 않는다.

대시보드는 긴 제목과 에이전트 ID를 노드 안에서 축약하고 전체 값은 툴팁과 상세 패널에 표시한다. 드릴다운 화면에는 현재 부모 작업도 기준 노드로 함께 표시하여 부모에서 직계 하위 작업으로 이어지는 선을 유지한다. `SUCCESS` 상태는 진행률 100%로 정규화한다.

## 추적 종료

이미 알고 있는 검증·문서·커밋·배포 같은 남은 범위까지 계획에 넣기 전에는 마지막 노드를 완료하지 않는다. 관련 후속 요청은 기존 완료 이력을 보존한 채 같은 workflow에 새 노드로 이어 붙인다. 최종 상태는 `SUCCESS`, `FAILED`, `BLOCKED` 중 하나이며 실제 남은 작업이 없을 때 마지막 이벤트 후 heartbeat를 중단한다. 이후의 무관한 요청은 완료된 그래프에 추가하지 않고 새 그래프로 시작한다.

## 이전 그래프 불러오기

```text
SMSR에서 이 프로젝트의 이전 그래프 목록을 보여줘.
```

에이전트는 `list_workflows(projectId)`로 최근 그래프의 workflow ID, 노드 수, `ACTIVE`·`TERMINAL` 상태와 마지막 활동 시각을 조회한다. 사용할 항목을 정한 뒤 다음처럼 요청한다.

```text
workflowId가 sample-build인 그래프를 불러와 이어서 추적해줘.
```

선택된 그래프는 `get_plan`과 `get_state`로 불러오며 기존 workflow ID를 그대로 사용한다. 후보가 여러 개인데 지칭이 모호하면 에이전트가 임의로 새 그래프를 만들지 않고 선택을 요청한다.

## 기록하지 않는 정보

- 그래프를 요청하지 않은 일반 작업과 질문
- 사용자 프롬프트 원문
- 비밀, 토큰, 원시 셸 명령
- 모든 도구 호출의 세부 내역

전역 `UserPromptSubmit` 훅은 프로젝트와 task 식별자를 에이전트 컨텍스트에 제공한다. 활성 그래프가 있을 때만 정규화된 lifecycle·도구 메타데이터를 JSONL에 기록하며 SMSR DB에는 저장하지 않는다.
