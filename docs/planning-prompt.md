# 작업계획서 프롬프트 설정

SMSR은 Codex를 직접 호출하지 않는다. 사용자가 Codex에 요청을 보낼 때 SMSR의 `UserPromptSubmit` 훅이 현재 설정에 저장된 계획 정책을 추가 컨텍스트로 전달한다.

## 기본 흐름

1. 설정 탭의 `구현 전에 작업계획서를 보여주고 검토·승인받기`를 켠다.
2. 구현 요청을 보내면 Codex가 원래 요구사항을 추가하거나 변경하지 않은 계획서 초안을 먼저 제시한다.
3. 사용자가 승인하거나 수정을 요청한다.
4. 승인된 계획을 기준으로 구현한다.

검토 옵션을 끄면 계획 프롬프트는 Codex에 전달되지 않는다. 사용자가 특정 요청에서 계획 검토를 생략하라고 명시하는 경우에도 바로 진행할 수 있다.

기본 문구는 최초의 `prompts/workflow-graph-multi-agent-instructions.md`에서 현재 구조에도 유효한 형식만 가져온다. 목표·범위, 계층 작업, 선행 관계, 담당 역할, 완료 기준, 검증, 산출물, 3회 실패 중단과 최종 완료 판정을 포함한다. 프로젝트에 별도 작업지시가 있으면 그 지시가 우선이며 사용자 요청의 범위를 넓히지 않는다. 폐기된 JSON 상태 파일, polling과 대시보드 관리 에이전트 규칙은 포함하지 않는다.

## 프롬프트 편집

설정 탭의 다중행 입력란을 수정하고 다른 컨트롤로 포커스를 이동하면 현재 Windows 사용자 설정에 자동 저장된다. `기본값 복원`으로 제품 기본 문구를 되돌릴 수 있다.

- `{projectId}`: 현재 작업 폴더명
- `{taskId}`: 현재 Codex 작업 또는 세션 ID

프롬프트는 최대 6,000자이며 `%LocalAppData%\SMSR\settings.json`에 저장된다. SMSR 이벤트 데이터베이스나 작업 그래프에는 기록되지 않는다. 설치 경로는 문구에 포함되지 않으므로 다른 PC에서도 각 PC 사용자의 설정으로 다시 구성할 수 있다.
