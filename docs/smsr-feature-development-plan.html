SMSR 작업 관제 기능 확장 개발계획서

상태 신뢰성, 계획 분해, 사용자 개입, 근거 기반 질의, 사용자 등록 펫을 현재 구조 위에 단계적으로 확장한다.

작성 기준: 2026-09-16 · 날짜 기반 일정은 정하지 않고 기능 단계와 완료 게이트로 관리

1. 범위와 목표

핵심 목표
사용자가 5초 안에 현재 작업, 마지막 활동, 정체 여부, 차단 이유와 필요한 조치를 파악한다.
P0 상태정체·실패·차단·중단을 구분하고 활성 그래프를 요약한다.
P1 계획A 하나로 뭉친 작업을 A1/A2 하위 노드로 검증·전개한다.
P1 질의선택 범위의 저장 데이터만 근거로 요약·질의한다.
P1 펫등록된 한 마리가 선택 그래프의 상태를 읽기 전용으로 표현한다.

포함

상태·정체 판정, 차단 작업함, 노드별 상세·타임라인, 계획 분해 검사, 요약·질의, 단일 펫 등록·트레이 제어, 검색·필터·내보내기·템플릿의 단계적 도입, 자체검사·설치본 검증.

제외

벡터 DB·지식 그래프, 다중 펫, 게임화, 원격·클라우드 동기화, 무단 자동 재시작, 시간만으로 추측하는 그래프 생성, 외부 서비스 다중 연동.

3. 핵심 기능 설계

상태·정체·중단

PENDINGIN_PROGRESSVALIDATINGRETRYINGSUCCESSFAILEDBLOCKEDCANCELLED

lastEventAt, lastHeartbeatAt, updatedAt, 오류, 다음 조치를 분리한다. heartbeat만 있고 의미 있는 변화가 없으면 실패가 아닌 정체 가능성으로 표시한다.

활성 그래프·차단 작업함

현재 노드, 진행률, 마지막 활동, 정체·실패·차단 수를 요약하고, 사용자 결정·인증 만료·외부 대기·검증 실패를 조치 카드로 모은다. 자동 재시작은 하지 않는다.

계획 분해 품질

children을 parentNodeId 계층으로 저장한다. 독립 상태가 두 개 이상인 포괄 리프에는 분해 경고를 표시하고, 중복 ID·순환·완료 기준 누락을 저장 전에 검증한다.

노드 상세·질의

선택 노드의 상태·담당·결과·오류·완료 기준·산출물·활동만 표시한다. 요약·질의 팝업은 현재 그래프 선택과 별도로 특정 프로젝트 또는 전체 프로젝트를 고르고, 오늘 또는 달력의 단일 날짜·기간 기록을 사용한다. 질의는 프로젝트·그래프·기간·노드 범위와 기준 시각·근거·모델 오류를 함께 보여준다. IME 조합 중에는 재렌더링하지 않는다.

4. 사용자 등록 펫 1마리

역할
펫은 작업 상태의 읽기 전용 표현이며, 독립 상태를 만들거나 관제 데이터를 판단하지 않는다.
  • 사용자가 이름과 허용된 이미지·애니메이션 자산을 등록한다.
  • 트레이에서 표시·숨김, 크기, 투명도, 항상 위, 움직임 감소를 설정한다.
  • 현재 선택된 활성 그래프 하나만 따른다.
  • BLOCKED는 도움 요청, FAILED는 경고, SUCCESS는 짧은 완료 동작 후 휴식으로 표현한다.
  • 그래프 종료 후에는 자동으로 다른 그래프로 이동하지 않고 대기한다.
  • 경로 탈출·실행 파일·과도한 크기 자산은 차단하고 기본 펫으로 대체할 수 있다.

8. QA·개발 방법·커뮤니케이션

  • 단위: 상태 전이, 정체 판정, 계획 분해, 경로 검증
  • 통합: MCP 계획·이벤트·heartbeat·state·요약 왕복
  • 화면: 선택 노드 필터, 차단함, SSE, IME, 펫 등록·전환
  • 보안: localhost bind, DPAPI, 자산 경로 탈출, 로그 마스킹
  • 릴리스: Release/publish, stdio protocol·도구 수, 버전·SHA-256, PID 보존

한 기능을 계약·화면·자체검사·문서까지 묶어 완료하는 수직 슬라이스를 사용한다. 변경은 핵심 상태·사용자 개입·표현·고도화·보류로 분류하며, 막힘은 원인·영향·선택지·필요한 결정을 함께 보고한다.
