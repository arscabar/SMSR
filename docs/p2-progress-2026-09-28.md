## Python 정상 경로 제어 의존 (2026-09-29, 파일 분석 버전6)

- 기존 CPython 3.12 정상 전이 정규화를 재사용하고, 유한 종료 경로의 후지배와 조건별 명령 제어 의존을 추가했다. 비트셋 고정점은 기존 파일 전체 계산25만/출력5만 한도를 공유한다. 큰 CFG는 한도를 넘으면 부분 결과를 저장하지 않는다.
- 실제 명령의 TRUE/FALSE·NONE/NOT_NONE·반복 다음/소진을 저장한다. -1 합성 종료에는 반환과 명시적 raise를 연결한다. 도달 불가 명령을 제외하고 종료에 도달할 수 없는 영역이 있으면 `NON_EXIT_REACHABLE_REGION`으로 전체 제어 의존을 비운다. 종료 가능한 반복도 반드시 종료한다고 증명하지는 않는다.
- 예외 범위와 중단은 `EXCEPTION_REGIONS`/`SUSPENSION`으로 구분한다. 암묵적 예외·실제 경로 조건·안전성·함수 간 PDG/taint는 포함하지 않는다. 변수/값 분석과 제어 의존의 지원 상태는 독립적이다.
- 독립 정답집은 소형 그래프1000개에서 각 정점을 제거하고 남은 종료 경로를 탐색해 후지배·즉시 후지배·분기별 의존을 대조한다. Python 정답집은 짧은 반환 복제/긴 반환 합류·조기 반환·반복·for 종료 정규화·None 조건·예외/중단/비종료 및 계산/출력 제한을 검사한다. 대상 코드는 실행하지 않는다.
- 기존 화면/HTTP/MCP/SQLite 저장에 연결했으며 파일 분석 버전5 이하 결과는 stale이다. 전체16언어 정밀 의미 분석·PDG/taint와 최종 P2 수용은 미완료다.

## Java 정상 CFG·제어 의존 (2026-09-29, Java 버전4)

- 설치된 JDK17의 AST와 공용 후지배 알고리즘을 사용한다. if·단락/삼항·while/for/do·라벨 없는 break/continue·반환/명시 throw를 정상 전이로 연결한다. 표현식 피연산자의 순서를 보존하고 람다 본문은 즉시 실행 경로에 넣지 않는다.
- 도달 불가 노드를 제거한다. 합성 종료 -1에 도달할 수 없는 영역은 제어 관계를 비우고 `NON_EXIT_REACHABLE_REGION`을 반환한다. 정상 전이 자체는 별도 근거로 남는다. try/switch/확장 for/라벨/동기화/익명 클래스 초기화 등 미지원은 빈 CFG와 사유다.
- 유한 종료 경로 의미이며 실제 종료·불리언 리터럴 이외의 조건 만족성·암묵적 예외·호출 내부 효과·함수 간 제어/taint를 증명하지 않는다. 기존 값 그래프의 구문상 제어 후보와 별도 표로 표시한다.
- 버전4·입력 해시·리비전·노드 위치·정상 전이·즉시 후지배·분기별 관계를 기존 SQLite/HTTP/MCP에 저장한다. 원문/리터럴/진단 메시지 제외, 버전3 이하 stale, 삭제/변경 보호를 유지한다.
- 실제 JDK 빌드, 조건 조합별 단락/삼항 평가 순서·조기 반환/공유 반환·continue 갱신·무한 반복/예외 경계 및1000그래프 독립 후지배 정답집을 통과했다. 게시 앱6종·stdio44·Java/Python/TS/16문법/Cypher 회귀 통과. 전체16언어 정밀 P2는 미완료다.
- 언어 근거: [JLS17 정상/급격 완료·분기·반복](https://docs.oracle.com/javase/specs/jls/se17/html/jls-14.html), [javac 삼항식 AST](https://docs.oracle.com/en/java/javase/17/docs/api/jdk.compiler/com/sun/source/tree/ConditionalExpressionTree.html). 재현은 [Java 예제](../samples/graph-java/README.md).

## JS/TS switch 정상 경로 (2026-09-29, 묶음 버전7)

- 기존 AST CFG에 switch를 추가했다. 선택식을 한 번 평가하고 case 식을 소스 순서로 검색한다. 중간 default도 모든 case 불일치 뒤 선택한다. 일치 후에는 다음 조건식을 평가하지 않고 본문만 이어 실행한다.
- `SWITCH_VALUE`·`CASE_TEST`의 소스 위치와 `CASE_MATCH`/`CASE_NO_MATCH` 전이를 저장한다. 엄격 일치/불일치 경로이며 실제 값·실행 가능성을 계산하지 않는다. break는 가장 가까운 switch/반복 밖으로, continue는 바깥 반복의 갱신/조건으로 연결한다.
- default 없음/모든 위치·break 조합72배치와 선택/불일치/복수 일치360경로를 독립 목록 정답과 대조했다. 빈 switch/default-only/grouped case·중첩 switch/loop·명시 throw·미지원 try, 결정적 출력·문자열 비밀 제외·JS JSDoc 표본 및 기존 제어/후지배 검사를 통과했다. 대상 코드는 실행하지 않았다.
- 버전7 저장·조회 계약으로 바꾸고 버전6 이하 결과를 stale 처리한다. 값/도달 정의·함수 간 데이터 요약의 switch 지원은 별도 잔여이므로 해당 결과의 UNAVAILABLE을 유지한다. 예외·런타임 경로 만족성·전체16언어 정밀 PDG/taint도 잔여다.
- 실제 적용: 리비전38(591파일/1270노드/734관계), 버전7 최신·16함수·진단0. switchPick15노드/17전이/10관계, switchFall18/20/10. HTTP/MCP/SQLite·게시 앱6종·stdio44·기존 언어 회귀 통과. 화면의 CASE_MATCH/CASE_NO_MATCH 반환·브라우저 오류0 확인. 별도 백업 복원의 무결성·외래키·전체 행수 일치. 원문 질문 제외·전역 훅 미적용·Go SDK 설치 대기 유지.
- 근거: [ECMAScript CaseBlockEvaluation·엄격 일치](https://tc39.es/ecma262/multipage/ecmascript-language-statements-and-declarations.html#sec-caseblockevaluation). [예제 switchPick·switchFall](../samples/graph-typescript/README.md). 위 버전6 절은 이전 단계 검증 이력이며 현재 switch 제어 지원은 이 절을 따른다.

## JS/TS switch 값·반환 요약 (2026-09-29, 묶음 버전8)

- 기존 도달 정의·상태 합류·호출별 고정점 요약을 재사용했다. case 검색을 소스 순서로 평가하고 일치 시점의 상태를 보관한다. default는 모든 조건식을 거친 상태로 시작한다. 앞선 선택 상태에 뒤쪽 case의 대입을 섞지 않는다.
- 각 본문 진입과 이전 본문 fall-through를 합친 뒤 대입으로 정의를 교체한다. break 상태는 switch 종료, continue 상태는 외부 반복으로 전달한다. 중첩 switch/loop·블록 이름 가림·조기/암묵 반환과 전 경로 덮어쓰기를 구분한다.
- 224배치의 672개 독립 경로에서 입력→반환 도달 및 요약을 대조했다. 선택 조건 입력은 데이터 요약에서 제외하고 case 식의 실제 대입 입력은 포함한다. 함수 간 relay의 입력1·2/호출 간선2개, 덮어쓰기의 빈 영향 입력·외부 호출 미해석 격리·결정성을 검증했다. 초기 중첩 표본은 TS narrowing으로 모순된 case가 진단되어 내부 선택 인자를 별도로 바꿨다. 컴파일러 진단 정책은 유지했다.
- 버전8 저장/조회로 갱신하고 버전7 이하 stale를 검사한다. switch 값 후보와 호출 요약이 추가됐지만 실제 경로 만족성·예외·힙/별칭·호출 효과·함수 간 제어/정밀 taint·전체16언어 분석은 잔여다. 위 버전7의 switch 값 미지원 설명은 이전 이력이며 최신 범위는 이 절을 따른다.
- 실제 적용: 리비전39(594파일/1275노드/736관계), 버전8 최신·진단0·19함수. switchPick16값노드/24간선, switchFall21/32, switchRelayed13/11 및 호출 요약2개·입력1/2, switchKilled/switchErased 빈 영향 입력 확인. 게시 앱6종·stdio44·언어 회귀·HTTP/MCP/SQLite·화면·별도 DB 복원 검사가 통과했다. 운영 DB 미교체·원문 질문 제외·전역 훅 미적용·SDK 결정 대기 유지.

## Go 분석기 준비 (2026-09-29, SDK 결정 대기)

`src/SMSR.GoAnalysis`와 `scripts/build-go-analysis.ps1`에 명시적 단일 패키지 입력의 표준 Go 컴파일러 분석기·테스트 소스를 준비했다. 선언/참조/제네릭 타입·직접/인터페이스/함수값 호출·인자 순서/펼침·물리 UTF-16 위치를 다룬다. 상수/struct tag/원문 진단은 출력하지 않는다. 표준 라이브러리는 신뢰한 SDK에서 별도로 만든 export 자료만 읽도록 구성했다.

## 16개 대상의 상태

C#, Python, JavaScript, TypeScript, TSX, Java, Go, Rust, C, C++, Ruby, PHP, Kotlin, Swift, Scala, Lua의 최소 선언/호출 표본이 모두 통과했다. TSX는 독립 언어라는 의미가 아니라 기존 지원 목록의 별도 문법이다.

**16개 구문 검사는 의미 해소 완료가 아니다.** 기존 공통 분석의 호출은 `UNRESOLVED`, 선언은 `SYNTAX_ONLY`다. 별도로 C#/Java 입력 묶음의 실제 컴파일러 바인딩과 Python의 CPython 변수 저장소·바이트코드 근거를 추가했다. 전체 프로젝트/16개 대상 완료는 아니다. 프로젝트 참조·옵션·생성 코드, 런타임 dispatch, 함수 간 인자/반환 데이터 흐름, sanitizer/제어 의존의 언어별 구현·정답집이 필요하다. 기존 휴리스틱 결과를 정밀 PDG 또는 안전성 판정으로 승격하지 않는다.

현재 경로에서 확인한 도구는 .NET SDK 10.0.401, Node/npm, Python, Java 17이다. 나머지 분석 서버/SDK 설치 여부와 전용 설치 범위는 사용자 선택을 요청했다. 시스템 PATH·전역 Git 설정을 임의 변경하거나 구문 기반 결과로 전체 언어 완료를 선언하지 않는다.

## C# 명시적 파일 묶음 분석

- 기존 SDK Roslyn DLL을 참조하는 `SMSR.CSharpAnalysis`를 별도 프로세스로 빌드했다. 신규 패키지/SDK/언어 서버는 설치하지 않았다. 기존 .NET 10 런타임의 신뢰된 관리 프레임워크 참조만 사용한다. SDK 고지 파일은 분석기 출력에 함께 복사한다. 외부 배포의 라이선스/설치 수용은 별도 출시 검토 대상이다.
- 입력은 색인된 상대 `.cs` 경로 목록, 명시적 C# 버전(기본 `CSharp12`), 조건부 심벌이다. 최대 500파일, 파일당 2 MB/묶음 16 MiB. 경로 중복·탈출·원문 해시 불일치를 거부하고 전체 파일 해시와 색인 리비전을 저장한다. 본문·상수 문자열·컴파일러 원문 오류는 저장하지 않는다.

- 실제 csproj/솔루션 평가·NuGet/프로젝트 참조·implicit using·생성 코드·사용자 지정 빌드 옵션은 아직 반영하지 않는다. 분석 대상의 MSBuild·코드·analyzer·source generator를 실행하지 않는다. 속성/이벤트/연산자 등 모든 암묵적 호출 종류와 프로젝트별 의미 정답집도 남아 있다.
- 양성/음성 표본: 다중 파일 오버로드·alias·generic·extension·local shadowing·constructor·named/default argument, virtual/delegate/dynamic 구분, 모호한 overload·누락 이름·조건부 심벌, `#line` 외부 경로 위장 거부, 원문 문자열 미노출, 입력 경로 보호. 물리 파일 경로/줄과 UTF-16 열을 근거로 사용한다.
- 재현 예제는 [samples/graph-csharp/README.md](../samples/graph-csharp/README.md)이며, 원래 16개 언어 목표를 C#으로 축소한 것이 아니다. 나머지 분석기 설치 범위는 여전히 답변 대기다.

## C# 컴파일러 제어·변수 흐름 추가

- 같은 묶음 분석 결과의 `functions`에 명시적 메서드·생성자·접근자·표현식 속성/인덱서와 내부 지역 함수·람다의 Roslyn CFG를 추가했다. `COMPILER_CFG`, 컴파일 오류가 있는 `COMPILER_CANDIDATE`, 본문/CFG가 없는 `NO_CFG`를 구분한다. 최상위 문장·필드 초기화·암묵적 생성 멤버는 아직 이 목록의 범위가 아니다.
- 각 함수의 블록에는 순번·종류·도달 가능성·조건 분기 기준, 일반/조건 후속 블록과 전이 의미, finally 경유 영역을 저장한다. catch/finally/변수 영역은 별도로 보존한다. 컴파일러의 암묵적 예외 전파를 모든 런타임 예외 간선으로 확장했다고 주장하지 않는다.
- 연산은 블록의 `operations`와 `branchValue`별로 순서·종류·물리 소스 위치·심벌/매개변수 ID를 보존한다. 연산 ID와 부모 ID는 각각의 배열 안에서만 유효하며, 전체 식별에는 함수 ID·블록 순번·배열 종류를 함께 사용한다. 상수 값·원문 텍스트는 포함하지 않는다.
- `variables`는 본문 영역에 대한 Roslyn `AnalyzeDataFlow` 결과다. 선언/읽기/쓰기/유입/유출/항상 할당/캡처 목록을 저장하며 미지원 영역은 `UNAVAILABLE`이다. 중첩 함수의 구문도 포함될 수 있다. 이 목록은 변수 간 def-use 간선, 실제 호출 실행, 함수 간 taint 또는 sanitizer 판정이 아니다.
- 함수/블록/영역/연산/변수 요약 항목의 합계 4만 한도를 초과하면 부분 결과를 성공으로 저장하지 않고 전체 요청을 거부한다. 기존 프로세스 시간/출력 크기 제한도 유지한다.
- 경계 실측: 8,500개 복합 할당은 연산 34,001개로 정상 분석됐다. 11,000개 할당은 실제 `Flow node limit exceeded`로 거부됨을 정답집에 고정했다. 공개 프로세스 응답에는 원문 예외 대신 일반 오류만 반환한다.
- 지역·익명 함수는 Roslyn 문서 ID만 쓰면 서로 다른 상위 함수 안에서 충돌할 수 있음을 시험으로 확인했다. 공통 `SymbolFacts.Id`에서 이 두 종류를 물리 파일 위치 ID로 바꾸어 선언·호출·CFG에 동일하게 적용했다. 서로 다른 상위 함수의 동명 지역 함수와 동일 시그니처 람다를 구분하는 회귀를 추가했다.
- CFG 단계의 저장 보고서는 버전 3이었다. 현재 버전 4는 버전 없는 이전 결과와 버전 2·3을 파일 해시가 같아도 갱신 필요로 판정한다. 기존 화면·HTTP·MCP·SQLite 경로를 재사용하고 화면에 함수별 요약과 분기/예외 영역 상세를 제공한다.
- 표현식 속성/인덱서는 선언 노드의 연산이 없으므로 getter 소속 루트 연산에서 CFG를 생성한다. 생성자·소멸자·표현식 getter·인덱서·연산자는 `FlowMembersSelfCheck`로 확인하고, 본문 없는 자동 접근자는 `NO_CFG`로 남긴다.
- `FlowSelfCheck`/`FlowBoundarySelfCheck`는 분기·반복 역간선·반환·미도달·지역/익명 함수·catch/finally·외부 `#line`·한국어/UTF-16·인자/매개변수 ID·컴파일 오류 하향·원문 미노출을 검사한다. `GraphCSharpVersionSelfCheck`는 저장된 흐름과 구버전 갱신 판정을 실제 MCP 조회로 검사한다.

근거 API: [Roslyn ControlFlowGraph](https://learn.microsoft.com/en-us/dotnet/api/microsoft.codeanalysis.flowanalysis.controlflowgraph?view=roslyn-dotnet-5.0.0), [Roslyn DataFlowAnalysis](https://learn.microsoft.com/en-us/dotnet/api/microsoft.codeanalysis.dataflowanalysis?view=roslyn-dotnet-5.0.0).

## C# 함수 간 입출력 연결 근거

- 결과 `functions[].boundary`는 매개변수 ID·순번·이름·타입·ref 종류·optional/params·선언 위치, 반환 종류, 수신 객체 식별자를 제공한다. `calls[].arguments`는 컴파일러 순번과 식 위치·매개변수 ID·암묵성·인자 입출력 변환 정보·배열 요소 위치를 보존한다. 실제 값·기본값·리터럴은 저장하지 않는다.
- `connections`는 각 호출의 문맥을 유지한다. 묶음에 유일하게 확인된 직접 호출 본문의 매개변수 슬롯에 인자를 연결하고, 도달 가능한 반환 블록의 값을 해당 호출 결과의 후보로 연결한다. 이름 있는 인자 순서, 기본 인자, 확장 메서드의 첫 매개변수, params 배열 요소, partial 구현의 매개변수를 구분한다. 재귀는 순환 연결만 보존하고 무한 전개하지 않는다.
- `BOUNDARY_LINKED`는 **입출력 근거 연결**이다. 일반 값 인자는 `ARGUMENT_PARAMETER`, 참조 인자는 `REFERENCE_ALIAS_REQUIRED`, 반환은 `MAY_RETURN_TO_CALL`이다. 경로 조건·반환값의 def-use·참조/힙 별칭·캡처 환경·암묵적 변환 부작용·taint·sanitizer 계산은 별도 잔여 작업이다. 객체를 값으로 전달해도 객체 내부 상태까지 분석한 것이 아니다.
- 가상/delegate/제약 타입 디스패치는 정적 대상만 남긴다. 정적 virtual 인터페이스 메서드도 제약 호출이면 인터페이스 기본 본문에 확정 연결하지 않는다. 동적 생성자도 동적 호출로 표시한다. 조건부 메서드는 `CONDITIONAL_CALL`, 본문이 없는 외부 함수는 `NO_SOURCE_BODY`, 컴파일 오류·모호함은 별도 상태로 남기며 반환 연결을 만들지 않는다.
- async 결과·iterator·ref/ref readonly 반환·생성 객체는 일반 반환식에서 호출 결과로 연결하지 않는다. await/state machine·yield 열거·참조 별칭·할당된 객체 모델이 필요하기 때문이다. 메서드 자체의 인자 대응은 보존하며 반환 종류를 제한에 표시한다.
- 연결/인자/반환/수신 객체 항목 합계는 최대 2만이다. 150개 분기 반환과 200개 호출의 실제 컴파일 표본에서 연결 전개 초과가 전체 요청 거부로 처리됨을 검증한다. 출력 16 MiB·시간·프로세스 종료 계약은 기존과 같다.
- 저장 버전 4와 기존 HTTP/MCP 분석·조회에 연결했다. 화면의 호출별 `입출력 상세`에서 매개변수 선언과 반환 후보 위치를 확인한다. `GraphCSharpConnectionsSelfCheck`는 HTTP/MCP/DB의 다중 파일 입출력 근거를 검사한다. `Connection*SelfCheck`는 위 양성/음성·경계 사례를 검증한다.

의미 기준: [Roslyn IMethodSymbol](https://learn.microsoft.com/dotnet/api/microsoft.codeanalysis.imethodsymbol). 이 단계는 함수 간 전체 PDG 구현이나 16개 언어 완료를 대체하지 않는다.
