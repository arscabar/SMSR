# SMSR v1.4.0 통합 테스트 보고서

## 대상과 판정 기준

- 대상: 월간 작업 그리드, Gemini 보안 설정, 금일·선택일자 LLM 요약, Codex 대체 요약 MCP, 설치 업그레이드
- 판정 기준: Release 빌드와 자체 검사, stdio 초기화·도구 목록, 설치 파일 생성·검증이 모두 통과해야 한다.
- 데이터 안전: 기능 검사는 임시 데이터 폴더와 가짜 Gemini HTTP 응답을 사용하며 실제 API 키와 사용자 SQLite 이력을 수정하지 않는다.

## 구현 검토

- 날짜 그리드는 선택 월의 실제 날짜만 최대 31일 표시하고 앞뒤 빈 셀은 선택할 수 없다.
- 금일과 그리드 선택일자 요약은 현재 선택 프로젝트가 아닌 모든 프로젝트의 해당 날짜 그래프·일일 기록을 입력으로 사용한다.
- Gemini 키는 일반 설정 JSON과 분리해 Windows 현재 사용자 범위 DPAPI로 보호한다.
- Gemini 키가 없거나 API 호출이 실패한 경우에만 난수 요청 ID를 만들고 Codex 새 작업으로 전환한다.
- Codex에는 기록 원문 대신 요청 ID만 전달하고 보호된 SMSR MCP가 실제 요약 입력과 결과를 왕복한다.
- 완료 결과는 20,000자로 제한하며 존재하지 않거나 만료된 요청은 저장하지 않는다.

설치 EXE SHA-256은 `871C5FF0A870DD192F62A18413D8CDD80404DAAF5D0ED5752E7F3F5E31D89E6D`이며 크기는 63,396,661바이트다. publish와 실제 설치된 `SMSR.App.exe` SHA-256은 모두 `CADB77020C903CBBF66AAAC4862617DD3DD9689709B9FB187A68BF8AD08B5E7C`로 일치했다. 기존 `settings.json`과 SQLite 파일 해시는 업그레이드 전후 동일했다.

설치본 브리지를 서버·본체가 없는 상태에서 실행하자 `SMSR.App.exe` 한 개와 `127.0.0.1:49783` 서버가 자동 복구됐고 stdio에서 12개 도구를 반환했다. WPF UI Automation으로 월간 날짜 그리드, 두 요약 버튼, Gemini 키 저장·연결 확인·삭제 컨트롤을 확인했다.

최초 종합 검사에서는 한글이 JSON 안에서 Unicode escape된 값을 원문 문자열로 비교해 `daily-summary` 판정만 실패했다. 응답을 `JsonDocument`로 구조화해 판정하도록 수정한 뒤 전체 검사가 종료 코드 0을 반환했다.

## 남은 위험

- 실제 Gemini 키와 외부 API의 실호출은 릴리스 저장소에 비밀을 넣지 않기 위해 자동 검사에서 제외했다.
- Codex Desktop 새 작업은 사용자가 전송을 한 번 눌러야 하며, 설치 직후 실행 중이던 Codex는 MCP 도구를 다시 읽도록 완전히 재시작해야 한다.
- 별도 단위 테스트 프로젝트가 없고 주요 회귀 검증은 임시 저장소를 사용하는 실행 파일 자체 검사에 집중돼 있다.
