---
name: smsr-report
description: Produce an evidence-based SMSR architecture and knowledge report from a consistent graph snapshot, with coverage and explicit unknowns.
---

Confirm `get_graph_health` and discover actual schemas. Call `get_graph_report`; ANALYSIS_PENDING requires waiting the returned retryAfterSeconds and polling the same project. Stop on FAILED and report the failure. READY contains one revision's groups, core nodes, actual cross-group edges, rationale quotes, coverage and limitations.

Resolve important groups with `get_graph_group_members` at the report revision. Use `get_graph_question_evidence`, source viewers and `get_graph_feedback_lessons` to verify representative claims. If evidence revision differs, refresh the report; never mix snapshots. Inspect original source for roles not established by graph metadata and label the independent evidence.

Structure the report as: scope/revision, major components and supported roles, actual relationships and evidence, source-backed design reasons, significant cross-group connections, coverage gaps, and questions to verify next. Degree/group labels do not prove importance or purpose. Inferred edges are clearly separated from extracted facts. Missing media semantics or rationale is unknown, not a guessed explanation.

Cite source locations and analyzer/hash status. Preserve truncation and stale warnings. By default answer in chat; save/export only when requested, without raw questions or hidden reasoning. Never call providers, index, install hooks, modify source or upload project content just to write a report.
